# مشروع School - منصة إدارة المدارس والمؤسسات التعليمية

هذه الحزمة هي المرجع الهندسي والوظيفي الأول للمشروع، ويجب تحديثها مع كل قرار معماري أو تغيير جوهري.

## محتويات الحزمة
- `docs/00-المواصفات-الهندسية-الشاملة.md`: الوثيقة المرجعية الرئيسية.
- `docs/01-حدود-الوحدات-والاعتماديات.md`: حدود تطبيقات Django وقواعد التواصل بينها.
- `docs/02-مصفوفة-الأدوار-والصلاحيات.md`: الأدوار والصلاحيات الافتراضية.
- `docs/03-قواعد-البيانات-والعزل.md`: قواعد تصميم البيانات وعزل المدارس.
- `docs/04-مراحل-التنفيذ-ومعايير-القبول.md`: خارطة التنفيذ ومعايير اكتمال كل مرحلة.
- `docs/05-تنفيذ-المرحلتين-الثانية-والثالثة.md`: واجهات الهوية والجلسات وربط ملفات الأشخاص ودورة حياة الطالب وإعدادات التشغيل والترحيل.

- `docs/mobile/README_AR.md`: مرجع تطبيق الهاتف الموحد المبني باستخدام Expo + React Native.

## قاعدة العمل
هذه الوثائق تحدد ما ينبغي بناؤه، ولا تعني أن الوظائف نُفذت بالفعل. لا يبدأ التطوير العشوائي قبل تحويل كل مرحلة إلى مهام قابلة للاختبار. لا يجوز تجاوز قواعد عزل المدارس أو القيود المحاسبية الواردة فيها لتسريع التنفيذ.

## القرار المعماري الأساسي
يبدأ المشروع ببنية **Modular Monolith**: تطبيق Django واحد منظم إلى تطبيقات مستقلة ذات حدود واضحة، مع PostgreSQL مشتركة منطقياً متعددة المستأجرين. لكل مدرسة نطاق بيانات مستقل ودفاتر محاسبية مستقلة بالكامل. يمكن لاحقاً نقل مدرسة كبيرة إلى قاعدة مخصصة دون تغيير واجهات الاستخدام، إذا صممت طبقة الوصول بعقود واضحة.
