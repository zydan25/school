# تنفيذ المرحلة الرابعة — الإعداد الأكاديمي والبيانات المرجعية

**النطاق:** المرحلة الرابعة فقط من خارطة التنفيذ في `docs/04-مراحل-التنفيذ-ومعايير-القبول.md`.

## ما تم استكماله

- الإبقاء على نماذج الأكاديميات الحالية، مع تمكين سجل أكاديمي عام على مستوى المدرسة أو سجل خاص بفرع محدد.
- جعل التفرد في رموز السنوات والمراحل والصفوف والقاعات والشعب والمواد والفترات وأيام الدوام داخل النطاق الصحيح (عام أو فرع محدد)، مع السماح بتكرار الرمز نفسه في فرعين مختلفين.
- جعل السنة الحالية والفصل الحالي مستقلين لكل فرع، مع بقاء قيد مستقل للسجلات العامة المشتركة.
- فرض توافق الفرع عند ربط الفصل بالسنة، والصف بالمرحلة، والشعبة بالسنة والصف والقاعة، ويوم الدوام بالفترات. يمكن لسجل الفرع استخدام سجل مرجعي عام، ولا يمكنه استخدام سجل مملوك لفرع آخر.
- منع الفترات الزمنية النشطة المتداخلة ضمن نطاق المدرسة العام أو الفرع نفسه، مع السماح لاختلاف أوقات الفترات بين فرعين مستقلين.
- فرض سعات موجبة للقاعات والشعب، والتحقق من ترتيب الفترات المرتبطة بأيام الدوام.
- إضافة عقد إدارة الفروع إلى واجهة API الحالية `/api/v1/app/branches/`، وإتاحة حقل `branch` في عقود الأكاديميات فقط؛ بقي حقل المدرسة للقراءة فقط ويحدده الخادم.
- إضافة مرشح `branch_id` إلى واجهات الإعداد الأكاديمي، ويعيد السجلات الخاصة بالفرع والسجلات العامة المشتركة فقط.
- ربط ملف الطالب وسجل القيد السنوي وسجل الحركة بالفرع نفسه، مع التحقق من عدم خلط سنة أو صف أو شعبة فرع آخر عند التسجيل أو الترفيع أو الإعادة أو النقل؛ تستخدم عمليات الترفيع والإعادة شعبة الفرع أولاً ثم الشعبة العامة المشتركة كخيار صالح.
- تمكين تقويم منفصل للفرع أو تقويم عام للمدرسة، وربط أيام التقويم بالفرع والسنة، وقراءة أيام الدوام من إعداد المدرسة مع السماح للفرع بتجاوز الإعداد العام. عند فحص يوم دراسي، تكون أولوية سجل الفرع قبل السجل العام.

## العقود الحالية التي أُعيد استخدامها

لم تُنشأ نماذج بديلة للسنوات أو الفصول أو المراحل أو الصفوف أو الشعب أو القاعات أو المواد أو الفترات أو أيام الدوام. كما لم تُكرر واجهاتها الحالية؛ التعديلات تمت على المسارات المسجلة بالفعل في مساحة API الحالية، وأضيف مسار الفروع فقط لعدم وجود عقد فروع في تلك المساحة.

دورة الترفيع والإعادة والنقل وسجل الحركة موجودة بالفعل في `apps/students/services.py` و`apps/students/models.py`؛ تم تعزيزها بعزل الفرع وإعادة استخدام مساراتها الحالية دون إنشاء مسار ترفيع بديل.

## التحقق

تضيف اختبارات المرحلة تغطية لعزل الفروع، وتكرار الرموز بين الفروع، والتوافق بين العلاقات الأكاديمية، والفترات المتداخلة، والسعات، وعقود API والمرشح `branch_id`، وربط قيد الطالب بالفرع، ومنع ترفيعه عبر الفروع، وتوليد التقويم بحسب أيام الدوام وأولوية تقويم الفرع. يجب اعتماد المرحلة بعد نجاح CI على SQLite وPostgreSQL.

## حدود التنفيذ

لم تتضمن هذه الدفعة أي تغيير في الجدول أو الحضور أو الأعذار أو التقارير أو خدمات المرحلة الخامسة.
