# الوثيقة الهندسية والوظيفية الشاملة
## منصة School لإدارة المدارس والمؤسسات التعليمية

**الإصدار:** 1.0 | **الحالة:** مواصفة تأسيسية | **اللغة:** العربية مع دعم تعدد اللغات | **المنصات:** Backend مستقل + React Web + Expo + React Native

---

# 1. الملخص التنفيذي والرؤية

يهدف مشروع **School** إلى بناء منصة تعليمية وتجارية متعددة المدارس (Multi-Tenant School ERP / SaaS)، لا مجرد برنامج لإدارة سجل الطلاب. تدير المنصة مدارس ومجمعات تعليمية ورياض أطفال ومعاهد ومراكز تدريب من حساب مركزي واحد، مع توفير بيئة مستقلة لكل مؤسسة تعليمية.

يتكون النظام من مستويين منفصلين:
1. **مستوى المنصة المركزية:** إنشاء المدارس وتفعيلها وإيقافها، إدارة الباقات والاشتراكات وحدود الاستخدام والدعم الفني والإعدادات العامة.
2. **مستوى المدرسة:** مساحة تشغيل مستقلة تشمل الإعدادات والفروع والسنوات والطلاب والموظفين والجدول والحصص والواجبات والدرجات والتواصل والمالية والمحاسبة والتقارير.

الاستقلال ليس مجرد إخفاء بيانات مدرسة عن أخرى في الواجهة. لكل مدرسة سجلاتها الأكاديمية والإدارية والمالية ودفاترها المحاسبية وسياساتها التشغيلية. لا تختلط أرصدة المدارس أو سنداتها أو قيودها أو طلابها أو درجاتها أو ملفاتها.

## 1.1 أهداف المنتج
- إدارة عدد كبير من المدارس من منصة موحدة مع عزل صارم للبيانات.
- لوحة ويب مستقلة لكل مدرسة، وتطبيق Expo + React Native موحد يخدم الجميع بحسب عضوية المستخدم ودوره.
- ربط العمليات اليومية في مسارات متكاملة: تسجيل طالب، استحقاق رسوم، تحصيل، قيد محاسبي، إشعار، تقرير.
- إدارة أكاديمية دقيقة تشمل الصفوف والشعب والمواد والحصص والجداول والواجبات والحضور والاختبارات والدرجات والشهادات.
- محاسبة حقيقية بالقيد المزدوج، مستقلة لكل مدرسة.
- صلاحيات على مستوى المدرسة والفرع والسجل والعملية، لا على اسم الدور فقط.
- دعم الويب والهاتف والإشعارات متعددة القنوات وسجل التدقيق.
- جعل الوحدات قابلة للتفعيل حسب احتياج المدرسة وباقتها دون كسر بقية النظام.
- قابلية التوسع والاستيراد والتصدير والنسخ الاحتياطي والاستعادة.

## 1.2 مبادئ غير قابلة للتفاوض
1. عزل المدارس إلزامي في كل طلب ومهمة خلفية وملف وتقرير.
2. لكل مدرسة دفتر أستاذ ودليل حسابات وفترات مالية وسندات وقيود وأرصدة مستقلة.
3. القيود والسندات المرحلة لا تحذف ولا تعدل بصمت؛ تصحح بعكس أو تسوية موثقة.
4. كل عملية حساسة لها أثر تدقيقي: من نفذها، متى، من أي مدرسة، وما الذي تغير ولماذا.
5. لكل وحدة منطقها وخدماتها وواجهات التكامل الخاصة بها؛ لا تنشئ سجلات وحدات أخرى مباشرة.
6. الواجهة ليست طبقة حماية؛ الخادم هو المرجع النهائي للصلاحيات.
7. البيانات الأكاديمية مؤرخة؛ انتقال الطالب أو تغير المعلم لا يمحو التاريخ.
8. الخصومات الكبيرة، إلغاء السندات، إغلاق الفترات، نشر النتائج وتصحيح الدرجات بعد النشر تخضع للاعتماد.
9. يبدأ النظام منظماً كتطبيق واحد، ولا يقسم إلى خدمات صغيرة قبل وجود حاجة حقيقية.

## 1.3 مصطلحات أساسية
| المصطلح | المقصود |

| المنصة | النظام المركزي الذي يملكه مشغل School |
| المدرسة / المستأجر | مؤسسة تعليمية مستقلة داخل المنصة |
| الفرع | موقع أو حرم تابع لمدرسة واحدة |
| السنة الدراسية | دورة أكاديمية مثل 2026-2027 |

# 2. النطاق العام ومكونات المنتج

## 2.1 واجهات الاستخدام
- لوحة مالك المنصة لإدارة المدارس والاشتراكات والتفعيل والدعم ومراقبة الخدمة.
- لوحة إدارة المدرسة بجميع الوحدات وفق الصلاحيات والوحدات المفعلة.
- بوابة المعلم: الجدول والحصص والحضور والواجبات والدرجات والمواد والرسائل.
- بوابة الطالب: الجدول والواجبات والتسليمات والنتائج المنشورة والحضور والإعلانات.
- بوابة ولي الأمر: الأبناء المرتبطون به والحضور والرسوم والنتائج والواجبات والرسائل.
- تطبيق Expo + React Native موحد يتعرف على المدرسة أو المدارس المصرح بها ويعرض التجربة حسب الدور.
- واجهات خدمة اختيارية مثل كشك الحضور وشاشة الاستقبال وبوابة الدفع والتكاملات الخارجية.

## 2.2 أنواع المؤسسات
يدعم النظام المدارس الأهلية والخاصة والحكومية والمجمعات التعليمية متعددة المراحل ورياض الأطفال والمعاهد ومراكز التدريب والمؤسسات ذات الفروع. تكون الاختلافات في الإعدادات والتسميات والسياسات، لا في نسخ جداول متكررة. ويمكن للمعهد استخدام الدورات والمجموعات بدلاً من الصفوف السنوية مع الاستفادة من الطلاب والمدربين والحضور والرسوم والمحاسبة.

## 2.3 الأساسيات والميزات الاختيارية
**أساسي:** المدارس والفروع، الهوية والصلاحيات، السنوات والصفوف والشعب، الطلاب وأولياء الأمور، الموظفون والمعلمون، المواد والجدول، الحضور، الواجبات، الاختبارات والدرجات، الرسوم والتحصيل، المحاسبة، الإشعارات، الملفات والتقارير.

**اختياري حسب الباقة:** المكتبة، النقل، المخزون والمشتريات، الأصول، العيادة، المقصف، التعلم الإلكتروني المتقدم، الدفع الإلكتروني، GPS للحافلات، الرسائل الجماعية المدفوعة، الموقع العام.

# 3. البنية والمعمارية التقنية

## 3.1 النمط المعماري
التوصية هي **Modular Monolith**: Backend واحد باستخدام Django، مقسم داخلياً إلى تطبيقات نطاقية مستقلة. يمنح ذلك حدوداً واضحة وسهولة في التطوير والنشر والمعاملات، دون كلفة تشغيل خدمات صغيرة كثيرة مبكراً.

لكل وحدة نماذج بيانات ومسؤولية، خدمات تطبيقية، سياسات صلاحيات، API، أحداث أعمال، مهام خلفية، اختبارات ووثائق. يمنع استيراد منطق داخلي عشوائي من وحدة أخرى؛ التكامل يتم عبر خدمات معلنة أو أحداث نطاقية موثقة. ويمكن استخراج وحدات إلى خدمات مستقلة لاحقاً مع الحفاظ على العقود.

## 3.2 المكدس التقني
| الطبقة | الاختيار |
|---|---|
| Backend | Python + Django بإصدار مستقر ومدعوم عند بدء التنفيذ |
| API | Django REST Framework + OpenAPI |
| قاعدة البيانات | PostgreSQL |
| Web | React + TypeScript |
| Mobile | Expo + React Native |
| المهام الخلفية | Celery |
| Cache / Broker | Redis |
| الملفات | تخزين كائنات متوافق مع S3 أو تخزين خاص خلف واجهة موحدة |
| التشغيل | Nginx + Gunicorn، وDocker عند ملاءمة بيئة النشر |
| الاختبار | pytest واختبارات API وE2E |
| المراقبة | سجلات منظمة وتتبع أخطاء ومؤشرات أداء |

تثبت إصدارات المكتبات في ملفات قفل، وتحدث دورياً بعد اختبارات التوافق والأمان. لا يتصل React أو Expo + React Native بقاعدة البيانات مباشرة؛ جميع الاتصالات عبر API موثق.

لا توضع كل النماذج في ملف واحد، ولا تجمع المحاسبة والطلاب والجدول في تطبيق عام.

## 3.4 طبقات كل وحدة
- `models/`: نماذج البيانات والعلاقات والقيود.
- `selectors/` أو `queries/`: استعلامات القراءة مع نطاق المدرسة.
- `services/`: حالات الاستخدام وتغييرات البيانات داخل معاملات.
- `api/`: serializers وviews وurls وpermissions.
- `events/`: أحداث النطاق وعقودها.
- `tasks/`: المهام الخلفية.
- `tests/`: اختبارات المجال والتكامل والصلاحيات والعزل.

لا توضع قواعد الأعمال المعقدة في View أو Serializer أو React. صحة العملية تفرض في خدمات الخادم وقاعدة البيانات.

## 3.5 دورة الطلب
1. التحقق من الهوية.
2. تحديد سياق المدرسة من نطاق موثوق أو اختيار مدرسة مصادق عليه.
3. التحقق من عضوية المستخدم وحالة المدرسة والفرع.
4. تحميل الصلاحيات والميزات المفعلة.
5. التحقق من الإجراء والسجل.
6. تنفيذ الخدمة داخل معاملة عند الحاجة.
7. تسجيل التدقيق وإصدار الحدث بعد نجاح المعاملة.
8. معالجة الإشعارات والتقارير والمرفقات في الخلفية.

# 4. تعدد المدارس والعزل والاستقلال

هذا أهم قرار في المشروع.

## 4.1 نموذج المستأجرين
تحتوي قاعدة البيانات على سجلات مركزية للمنصة وسجلات تشغيلية للمدارس. كل جدول تابع لمدرسة يحمل `school_id` صريحاً، حتى إن أمكن استنتاج المدرسة عبر علاقة أخرى. يكون لكل مدرسة:
- معرف داخلي ثابت وكود فريد مثل `SCH-000123`.
- اسم رسمي وتجاري وشعار وهوية بصرية.
- اللغة والمنطقة الزمنية والتقويم والعملة الأساسية.
- فروع ومبانٍ وغرف.
- سنوات وفصول دراسية.
- مستخدمون وعضويات وأدوار.
- طلاب وأولياء أمور ومعلمون وموظفون.
- إعدادات أكاديمية وجداول ودرجات.
- سياسات رسوم وخصومات.
- دليل حسابات ودفتر أستاذ وفترات مالية وسندات وأرصدة مستقلة.
- قوالب إشعارات ومستندات وشهادات.
- ملفات ومرفقات وتقارير خاصة بها.

## 4.2 استقلال المحاسبة
لكل مدرسة دفتر محاسبي مستقل ولو كانت المدارس في PostgreSQL نفسها. لا يوجد حساب يحمل أرصدة مدارس متعددة، ولا قيد يحتوي سطوراً لمدرستين.
- كل `account` تابع لمدرسة واحدة.
- كل `journal_entry` تابع لمدرسة وفترة مالية واحدة.
- كل `journal_line` تابع لقيد وحسابه من المدرسة نفسها.
- كل صندوق وبنك ومركز تكلفة وعميل ومورد تابع للمدرسة.
- أرقام السندات والقيود متسلسلة بصورة مستقلة لكل مدرسة ونوع وفترة وفق السياسة.
- أي تقرير تجميعي بين المدارس للمنصة هو للعرض الإداري فقط، وليس دفتر قيد مشتركاً.
- لا ينقل قيد بتغيير `school_id`؛ إن سمح العمل، يتم نقل افتتاحي موثق ومعتمد.

ينشأ لكل مدرسة دليل حسابات من قالب، ثم يصبح ملكاً لها ويمكن تخصيصه. لا تشارك المدارس سجلات دليل الحسابات ذاتها.

## 4.3 طبقات العزل
1. `Tenant Context` إلزامي؛ لا يسمح باستعلام نطاقي دون سياق مدرسة.
2. كل Selector يضيف نطاق المدرسة تلقائياً.
3. فحص ملكية السجل والصلاحية عند الوصول بالمعرف.
4. قيود مركبة مثل `UNIQUE(school_id, code)` لمنع الربط العرضي.
5. يمكن تفعيل PostgreSQL RLS كدفاع إضافي، لا بديلاً عن صلاحيات التطبيق.
6. اختبارات سلبية لكل قراءة وتعديل وحذف وتنزيل بين مدرستين.
7. كل مهمة خلفية تحمل `school_id` صراحة.
8. الملفات بروابط مؤقتة بعد فحص الصلاحية ومسارات تخزين خاصة.
9. التقارير والتصدير تتطلب نطاق المدرسة وتحتفظ به في بيانات المهمة.
10. دخول الدعم الفني لمدرسة عبر تفويض مؤقت مسجل، لا بتجاوز صامت للعزل.

## 4.4 المستخدم والعضويات
يمكن للشخص امتلاك حساب دخول واحد وعضويات متعددة في مدارس مختلفة، دون دمج بيانات المدارس:
- `User`: هوية الدخول.
- `SchoolMembership`: عضوية وحالة وتواريخ المستخدم في المدرسة.
- `RoleAssignment`: الأدوار في المدرسة أو الفرع.
- `PermissionGrant`: صلاحيات استثنائية عند الحاجة.
- `GuardianStudentLink`: العلاقة بين ولي الأمر والطالب وقيود الوصول.

معرفة كود المدرسة لا تمنح الوصول. الكود لاكتشاف المدرسة أو طلب الانضمام؛ أما الوصول فيتطلب عضوية نشطة أو دعوة مقبولة.

## 4.5 دورة حياة المدرسة
الحالات: `draft`, `pending_activation`, `active`, `suspended`, `expired`, `archived`.
- الإنشاء: سجل وكود وإعدادات أولية.
- التهيئة: فروع وعملة وسنة ودفتر ومدير أول.
- التفعيل: العمليات حسب الباقة.
- التعليق: إيقاف الدخول أو العمليات الجديدة وفق سياسة، مع السماح بقراءة/تصدير مخول عند الحاجة.
- انتهاء الاشتراك: إشعار وفترة سماح ثم سياسة قراءة فقط أو تعليق.
- الأرشفة: إيقاف العمليات والاحتفاظ بالسجلات.
- الحذف: لا يحذف سجل مدرسة لديها معاملات مالية نهائية قبل مراجعة الاحتفاظ والنسخ والالتزامات القانونية.

# 5. الإدارة المركزية للمنصة

هذه وحدة مستقلة عن إدارة المدارس ولا تستخدم دفتر المدرسة المحاسبي.

## 5.1 إدارة المدارس
- إنشاء مدرسة بمعالج خطوات، وتوليد كود فريد قابل للتخصيص إذا لم يتعارض.
- الاسم الرسمي والتجاري والنوع والبلد والمدينة والعنوان ووسائل التواصل.
- الشعار والوثائق والهوية البصرية.
- إنشاء الفروع أو ترك إدارتها لمدير المدرسة.
- دعوة المدير الأول برابط آمن ومدة صلاحية.
- تحديد اللغة والمنطقة الزمنية والعملة الافتراضية.
- إعداد السنة الأولى ودليل الحسابات الابتدائي.
- تفعيل الوحدات الافتراضية وفق الباقة.
- استنساخ إعدادات نموذجية فقط، دون نسخ بيانات المدرسة الأخرى.
- عرض حالة المدرسة والاستخدام والأخطاء وسجل النشاط.

## 5.2 الباقات والاشتراكات
- تعريف الباقات والميزات والوحدات المسموح بها.
- مدة الاشتراك والسعر والعملة ودورية الفوترة.
- الحدود: عدد الطلاب النشطين، المستخدمين، الفروع، مساحة الملفات، الرسائل.
- إضافات مدفوعة وكوبونات وخصومات وفترة تجريبية.
- فواتير اشتراك المنصة وعمليات السداد والتجديد.
- الانتهاء والتعليق وفترة السماح وسجل تغييرات الباقة.

**فصل مالي:** إيرادات اشتراك المنصة تخص مشغل School ولا تدخل في إيرادات مدرسة. فواتير الاشتراك ونظامها المالي منفصلان عن رسوم الطلاب ودفاتر المدارس. لا يرى محاسب المدرسة تفاصيل فواتير المنصة إلا وفق صلاحية خاصة.

## 5.3 الدعم والمراقبة
- حالة الخدمات والمهام الخلفية والتخزين.
- عدد المدارس النشطة ومؤشرات الاستخدام.
- تذاكر الدعم وتصنيفها وتوجيهها وحالاتها.
- جلسة دعم مؤقتة بموافقة مدير المدرسة، محددة الوقت، وتسجيل كل إجراء.
- إعلانات المنصة وإصداراتها وسجل الإشعارات المركزية.

# 6. وحدات المدرسة بالتفصيل

## 6.1 إعدادات المدرسة والهيكل التنظيمي
المسؤولية هي تعريف الهوية والسياسات والهيكل الذي تعتمد عليه بقية الوحدات.
- ملف المدرسة والشعار والألوان وبيانات التواصل والنوع.
- الفروع والمواقع والمباني والطوابق والغرف والمختبرات والملاعب.
- الأقسام الإدارية والأكاديمية.
- أيام الدوام وساعات العمل والعطل.
- اللغة والمنطقة الزمنية والعملة الأساسية والتنسيقات.
- التسميات المحلية مثل الصف أو المجموعة.
- سياسات القبول والغياب والتأخير والتقييم والترحيل.
- إعدادات الخصوصية وموافقات أولياء الأمور.
- تفعيل الوحدات والميزات.

تُحفظ نسخ مؤرخة من السياسات الحساسة. تغيير سياسة الدرجات أو الرسوم لسنة جديدة لا يعيد احتساب سجلات السنوات السابقة تلقائياً.

## 6.2 السنوات والتقويم الأكاديمي
- تعريف السنة الدراسية وتواريخ بدايتها ونهايتها وحالتها.
- تقسيمها إلى فصول أو فترات أكاديمية مرنة.
- تقويم الأيام الدراسية والعطل الرسمية والمحلية.
- أيام الاختبارات والإجازات والفعاليات.
- مواعيد التسجيل والحذف والإضافة.
- ربط كل تسجيل طالب ودرجة وحضور وجدول بسنة صريحة.
- فتح السنة وإقفالها وترحيل الطلاب مع حفظ التاريخ.
- تقويم مستقل للفرع أو المرحلة عند الحاجة.

لا تستخدم السنة الحالية كقيمة ضمنية للسجلات؛ يجب حفظ السنة الدراسية المرتبطة بكل سجل تاريخي.

## 6.3 القبول والتسجيل
- طلبات تقديم إلكترونية أو تسجيل داخلي.
- بيانات مقدم الطلب والطالب وولي الأمر.
- المدرسة والفرع والمرحلة والصف المطلوب.
- الوثائق المطلوبة وفحص اكتمالها.
- اختبار قبول أو مقابلة وقائمة انتظار.
- قبول أو رفض أو طلب استكمال أو انسحاب.
- تحديد الرسوم والمنحة الأولية عند الموافقة.
- تحويل المقبول إلى ملف طالب دون تكرار البيانات.
- رقم طلب ورقم طالب فريد ضمن المدرسة.
- طباعة استمارة القبول وعقد التسجيل.
- سجل تاريخي للحالات ومن اتخذ القرار.

الحالات المقترحة: مسودة، مقدم، ناقص، قيد المراجعة، موعد اختبار، مقبول، مرفوض، قائمة انتظار، انسحب، محول إلى طالب.

## 6.4 إدارة الطلاب
يحتوي ملف الطالب على:
- الرقم المدرسي والاسم بالعربية واللغة الثانية والصورة وبيانات الميلاد الأساسية.
- بيانات الاتصال والعنوان والوثائق.
- بيانات صحية ضرورية فقط بصلاحيات شديدة التقييد.
- ولي الأمر والعلاقات الموثقة.
- المدرسة والفرع والسنة والمرحلة والصف والشعبة.
- حالة الطالب وتاريخ الالتحاق.
- الانتقالات والترقيات والإعادة والانقطاع والتخرج.
- السجل الأكاديمي والنتائج السابقة.
- الحضور والغياب والتأخر والواجبات والأنشطة.
- الفواتير والمدفوعات والمنح والمتأخرات.
- المكتبة والنقل والعهد عند تفعيلها.
- السلوك والملاحظات وفق الصلاحيات.
- المستندات والمرفقات.

العمليات: تسجيل وتعديل، ترقية جماعية، نقل بين شعب وصفوف وفروع، إيقاف مؤقت، انسحاب، تحويل، تخرج، أرشفة واستعادة، استيراد Excel بقالب ومعاينة وفحص تكرار، طباعة بطاقة وملف مختصر وشهادة قيد.

**قاعدة تاريخية:** لا يستبدل الصف السابق عند الترقية. ينشأ تسجيل جديد للسنة الجديدة ويبقى تاريخ السنوات السابقة كما هو.

## 6.5 أولياء الأمور والأسرة
- ملف ولي الأمر ووسائل الاتصال واللغة المفضلة.
- ربطه بطفل واحد أو أكثر وتحديد نوع العلاقة.
- أكثر من ولي أمر للطالب الواحد.
- تحديد من يستلم الإشعارات ومن يرى الرسوم والنتائج.
- ولي أمر لديه أبناء في مدارس مختلفة بعضويات منفصلة.
- طلب تعديل بيانات العلاقة ومراجعتها.
- موافقات رقمية للرحلات أو التصوير أو الخدمات.
- سجل تواصل ومواعيد مقابلات.
- دعوة آمنة لربط حساب التطبيق دون عرض الطلاب قبل اعتماد العلاقة.

تراعى حالات الحضانة والوصاية وتقييد التواصل، مع إيقاف وصول ولي الأمر عند وجود قرار موثق.

## 6.6 المعلمون والموظفون والموارد البشرية
- ملفات المعلمين والموظفين والوظائف والأقسام.
- المؤهلات والخبرات والتخصصات والرخص المهنية.
- العقود والرواتب وتواريخ الخدمة والوثائق.
- توزيع المعلمين على المواد والصفوف والشعب.
- النصاب والحصص الأسبوعية والحدود القصوى.
- الحضور والانصراف والإجازات والاستئذان.
- البدائل والتكليف المؤقت.
- تقييم الأداء والتدريب والملاحظات.
- السلف والعهد والجزاءات والمكافآت.
- إنهاء الخدمة وإخلاء الطرف والأرشفة.

يُفصل ملف الموظف عن عضوية الدخول: قد يكون الموظف بلا حساب، وقد يحمل المستخدم أكثر من وظيفة. لا تظهر الرواتب إلا لمخولين.

## 6.7 الهيكل الأكاديمي والمواد والصفوف والشعب
- المراحل التعليمية والصفوف التابعة لها.
- الشعب داخل الصف والسنة والفرع مع السعة والغرفة.
- المسارات أو التخصصات.
- المواد ورموزها ووصفها وتصنيفها (أساسية، اختيارية، نشاط، عملية، مختبر).
- ربط المادة بالصف/المسار والسنة.
- عدد الحصص الأسبوعية المطلوبة.
- توزيع المواد والمعلمين.
- توصيف المنهج والوحدات والدروس والأهداف.
- إسناد الطلاب إلى الشعب.

**تمييز أساسي:** الصف مستوى تعليمي، والشعبة مجموعة طلاب، والحصة الزمنية فترة في اليوم، والدرس المجدول مادة لشعبة ومعلم ووقت ومكان. يجب ألا تختلط هذه المفاهيم في قاعدة البيانات.

## 6.8 الجدول المدرسي والحصص
هذه وحدة رئيسية مستقلة وليست جدولاً نصياً يكتبه المستخدم.

### الكيانات
- أيام الدوام لكل مدرسة وفرع.
- قوالب أوقات الحصص مع أوقات البداية والنهاية والاستراحات.
- السنة والفصل الأكاديمي.
- الصف والشعبة والمادة والمعلم والغرفة/المختبر.
- متطلبات المادة والمكان.
- نصاب المعلم وعدد الحصص الأسبوعية المطلوبة للمادة.
- الدرس المجدول `ScheduledLesson`.
- البديل أو تغيير الغرفة.
- نسخة الجدول وتاريخ سريانها.

### الخصائص
- جدول أسبوعي حسب اليوم والحصة.
- عرض حسب الشعبة أو المعلم أو الغرفة أو المادة.
- اختلاف الجداول بين الفروع والمراحل.
- استراحة وفسحة وطابور وأنشطة منفصلة عن الدروس عند الحاجة.
- جداول بديلة لأيام الاختبارات أو المواسم.
- نسخ: مسودة، قيد المراجعة، معتمد، منشور، ملغى.
- سجل التغيير والسبب ومن نفذه.
- طباعة وتصدير ومشاركة الجدول مع المعلم والطالب وولي الأمر.

### منع التعارض
لا يعتمد الجدول إذا وضع معلماً أو شعبة أو غرفة في حصتين متزامنتين، أو تجاوز نصاب المعلم دون موافقة، أو وضع درساً خارج دوام الفرع، أو أسند مختبراً مخالفاً لمتطلبات المادة، أو لم يحقق عدد الحصص الأسبوعية إلا باستثناء معتمد. تطبق الفحوصات في الخادم عند الحفظ والاعتماد، لا في الواجهة وحدها.

تدعم النسخة الأولى تحريراً واضحاً وكشف تعارضات واقتراح أوقات بديلة؛ ويمكن إضافة التوزيع الآلي لاحقاً.

### إدارة الحصة اليومية
يفتح المعلم حصته الحالية، يرى الشعبة، يسجل الحضور، يحدد الدرس الذي شرحه، يضيف واجباً أو ملاحظة أو مادة تعليمية. تصبح الحصة مرجعاً لما تم تدريسه فعلياً.

## 6.9 الدروس والخطط والمحتوى التعليمي
- خطة سنوية وفصلية للمادة وتوزيع المنهج على الأسابيع والحصص.
- أهداف ومخرجات التعلم.
- سجل ما تم شرحه في كل حصة.
- ملفات وروابط ومقاطع ومواد تعليمية.
- محتوى عام أو خاص بشعبة.
- ملاحظات استيعاب الطلاب.
- ربط الدرس بالواجب والاختبار والنتيجة.
- نسبة إنجاز المنهج مقابل الخطة.

## 6.10 الواجبات والمهام المنزلية
وحدة مستقلة مرتبطة بالمادة والشعبة والدرس وتشمل:
- عنوان ووصف وتعليمات ومرفقات وروابط.
- المادة والصف والشعبة والحصة المرتبطة والمعلم.
- تاريخ الإسناد وموعد التسليم والإغلاق.
- الدرجة القصوى ومعيار التقييم إن كان الواجب محسوباً.
- نوع التسليم: نص، ملف، صورة، رابط، أو دون تسليم.
- السماح بالتأخير أو المحاولات المتعددة وفق السياسة.
- تسليم الطالب ومرفقاته وتوقيت كل محاولة.
- الحالات: لم يبدأ، مسودة، مسلم، متأخر، معاد للتعديل، مصحح.
- تقييم المعلم وتعليقه وتاريخ التصحيح.
- نشر الدرجة للطالب وولي الأمر وفق الصلاحية.
- إحصاءات التسليم والتأخر وعدم التسليم.

تُحفظ نسخ المحاولات السابقة، ولا يستبدل الملف بصمت. أي تعديل للموعد أو الدرجة يسجل. يمكن إرسال تذكير قبل الموعد وبعده مع منع التكرار.

## 6.11 الحضور والغياب والتأخير
- حضور يومي وحضور لكل حصة.
- غياب بعذر أو دون عذر، تأخير بالدقائق، انصراف مبكر، إذن خروج وعودة.
- تسجيل فردي أو جماعي واستيراد من جهاز عند توفر التكامل.
- طلب عذر من ولي الأمر وإرفاق الإثبات ومراجعته واعتماده أو رفضه.
- سجل تعديل الحضور وسببه.
- تنبيه عند تجاوز حد غياب.
- تقارير يومية وأسبوعية وشهرية حسب الطالب والشعبة والمادة والمعلم.

القواعد: لا يتكرر سجل الطالب والحصة؛ يوم العطلة أو الحصة الملغاة لا يحسب غياباً؛ التعديل بعد الاعتماد يتطلب سبباً وصلاحية؛ المعلم يسجل حصصه المسندة فقط، والإدارة وفق نطاقها.

## 6.12 الاختبارات والتقييم والدرجات والنتائج
### إعداد التقييم
- نظام تقييم لكل مدرسة ومرحلة وصف وسنة.
- أعمال فصل وواجبات ومشاركة واختبارات شهرية ونهائية وعملية وشفهية.
- أوزان ونسب ومجموع نهائي وسلم درجات رقمي أو وصفي.
- حدود النجاح والرسوب والإعفاء وقواعد التقريب.
- درجات الغياب بعذر أو دونه والاختبار البديل.
- مواد لا تدخل في المعدل وفق السياسة.

### إدارة الاختبار
- الاختبار ونوعه ومادته وصفوفه وشعبه وتاريخه ومدته ومكانه.
- المراقبون واللجان وتوزيع المقاعد وقوائم الطلاب.
- بنك أسئلة اختياري ونماذج وطباعة.
- إدخال الدرجات أو استيرادها بقالب.
- مسودة ثم مراجعة واعتماد ثم نشر.
- اختبارات تعويضية وإعادة اختبار.

### دفتر الدرجات والنتائج
- دفتر لكل مادة وشعبة وفترة.
- المعلم يرى المواد والشعب المسندة إليه.
- التحقق من الحدين الأدنى والأقصى ومنع تكرار درجة التقييم.
- مراجعة القيم الشاذة والناقصة.
- اعتماد القسم أو الكنترول ثم قفل الدرجات ونشرها.
- تعديل المنشور بطلب تصحيح وسبب وموافقة.
- حساب المجموع والمعدل والتقدير والترتيب والنجاح والرسوب وفق سياسة محفوظة.
- كشوف وشهادات وسجل تغيير لكل درجة.
- الطالب وولي الأمر لا يريان إلا النتائج المنشورة.

حساب المعدلات يتم في الخادم بخوارزمية محددة ومختبرة، مع حفظ نسخة سياسة التقييم المستخدمة.

## 6.13 الانضباط والسلوك والإرشاد
- أنواع المخالفات والسلوك الإيجابي والوقائع وتاريخها ومكانها والأطراف والشهود.
- الإجراء والمتابعة ونقاط السلوك عند اعتمادها.
- إشعار ولي الأمر وفق السياسة.
- ملاحظات المرشد بسرية وصلاحيات مقيدة وخطط دعم.
- لا تظهر الملاحظات الحساسة في بوابة الطالب أو ولي الأمر تلقائياً.

## 6.14 الرسوم المدرسية وحساب الطالب
هذه الوحدة تدير **حساب الطالب التجاري والاستحقاقات**، بينما المحاسبة تسجل الأثر في الدفتر العام. وحدة الرسوم تفهم الطالب والفاتورة والقسط، ووحدة المحاسبة تفهم الحساب المدين والدائن.

### تعريف الرسوم والفوترة
- رسوم قبول وتسجيل ودراسة سنوية أو فصلية.
- كتب وقرطاسية وزي وأنشطة ورحلات وامتحانات.
- نقل ووجبات وخدمات إضافية.
- رسوم حسب المرحلة أو الصف أو الشعبة أو نوع الطالب، ثابتة أو متغيرة.
- هيكل رسوم لكل سنة، فاتورة عند التسجيل أو بداية السنة، أقساط بمواعيد استحقاق.
- رسوم خاصة لطالب بسبب معتمد، خصومات إخوة أو تفوق أو دعم أو منحة.
- إعفاء كامل أو جزئي بموافقة حسب حد الخصم.
- ترحيل رصيد سابق وفق سياسة واضحة.
- عرض الإجمالي والمدفوع والمتبقي والمستحق والمتأخر.

### التحصيل
- سند قبض نقدي أو تحويل أو شيك أو وسيلة إلكترونية.
- تحديد الصندوق أو الحساب البنكي وطريقة الدفع.
- توزيع دفعة على فاتورة أو عدة استحقاقات وفق سياسة واضحة.
- دفعة مقدمة ورصيد دائن.
- إيصال قابل للطباعة والإرسال.
- إلغاء سند غير مرحل حسب الصلاحية أو عكسه بعد الترحيل.
- استرداد مع سبب وموافقة وربط بالسند الأصلي.
- مطابقة كشف الطالب وإقفال صندوق التحصيل اليومي.

### تقارير الرسوم
- المستحق والمحصل والمتبقي والمتأخر.
- أعمار المتأخرات: 1-30، 31-60، 61-90، وأكثر.
- كشف حساب طالب وأسرة.
- التحصيل حسب الصندوق والفترة والموظف وطريقة الدفع.
- الخصومات والمنح والإعفاءات وأسبابها ومعتمدوها.
- توقع التدفقات من الأقساط.

لا تحذف فاتورة أو دفعة لها أثر مالي دون معالجة عكسية. لا تعدل دفعة موزعة على عدة فواتير دون إعادة احتساب التوزيع وتوثيقه.

## 6.15 المحاسبة المالية المستقلة لكل مدرسة
هذه وحدة أساسية وجوهرية، وليست شاشة دخل ومصروف. يجب أن تكون محاسبة مزدوجة متكاملة ولكل مدرسة دفتر مستقل كلياً.

### 6.15.1 الكيانات
- ملف الدفتر المالي والمدرسة.
- السنة المالية والفترات المحاسبية.
- دليل الحسابات ومراكز التكلفة والفروع.
- الصناديق والحسابات البنكية والعملات وأسعار الصرف.
- القيود اليومية ورؤوس القيود وسطورها.
- سندات القبض والصرف والتحويل.
- العملاء والموردون والذمم المدينة والدائنة.
- الميزانيات والأصول الثابتة ومجمع الإهلاك.
- الضرائب والرسوم عند الحاجة والتسويات البنكية والأرصدة الافتتاحية.

### 6.15.2 دليل الحسابات
ينشأ لكل مدرسة دليل خاص من قالب قابل للتخصيص، ويدعم شجرة متعددة المستويات، كوداً واسماً ونوعاً وطبيعة للحساب، حساباً تجميعياً أو تفصيلياً، السماح أو المنع من الترحيل المباشر، ارتباطاً بصندوق أو بنك، عملة، ومركز تكلفة إلزامياً لبعض الحسابات. الأنواع: الأصول والالتزامات وحقوق الملكية والإيرادات والمصروفات. التقارير تعتمد على نوع الحساب وشجرته، لا على أسماء ثابتة في الكود.

### 6.15.3 القيد المزدوج
- كل قيد مرحل متوازن مديناً ودائناً بالعملة الوظيفية.
- يرفض القيد غير المتوازن أو الذي يقع في فترة مغلقة.
- لا يقبل الحساب التجميعي في سطر قيد.
- الحساب ومركز التكلفة والصندوق والجهة يجب أن تتبع المدرسة نفسها.
- القيد المرحل لا يعدل ولا يحذف؛ يصحح بعكس أو تسوية جديدة.
- كل قيد آلي يحمل مصدره ومعرفه لمنع التكرار.
- أرقام القيود مستقلة لكل مدرسة وسنة/دفتر وفق السياسة.

### 6.15.4 الدورات والمستندات
قيد يومية، سند قبض، سند صرف، تحويل بين الصناديق والبنوك، فاتورة مورد، استحقاق رسوم طالب، قيد رواتب، قيد مشتريات ومخزون، قيد أصل وإهلاك، تسوية ومخصصات، قيد افتتاحي وإقفال، إشعار دائن أو مدين.

تمر المستندات بحالات مسودة، انتظار اعتماد، معتمد، مرحل، ملغى أو معكوس. يجوز اختصار بعض الحالات بسياسة المدرسة، لكن لا يجوز تجاوز ضوابط الترحيل.

### 6.15.5 التكامل المحاسبي مع الوحدات
أمثلة مبدئية قابلة للتخصيص من دليل الحسابات:
- إثبات استحقاق الرسوم: مدين ذمم الطلاب، دائن إيرادات الرسوم أو الإيرادات المؤجلة وفق السياسة.
- تحصيل نقدي: مدين الصندوق/البنك، دائن ذمم الطلاب.
- مشتريات مستهلكة: مدين المصروف أو المخزون، دائن المورد/الصندوق.
- الرواتب: مدين مصروف الرواتب، دائن الرواتب المستحقة؛ وعند الدفع مدين الرواتب المستحقة ودائن البنك/الصندوق.

هذه أمثلة توضيحية وليست قوالب ثابتة. تعتمد المدرسة سياسة الاعتراف بالإيراد والمصروف مع المحاسب المختص، ولا تفترض المنصة المعالجة القانونية أو المحاسبية الملائمة لكل بلد.

### 6.15.6 الصناديق والبنوك
- عدة صناديق وحسابات بنكية لكل مدرسة.
- أمناء صندوق ومستخدمون مخولون.
- أرصدة افتتاحية وإيداع وسحب وتحويل.
- إقفال وردية أو يوم ومطابقة الرصيد الفعلي.
- حدود للصرف والخصم.
- مطابقة كشف البنك وتسوية الفروقات بمستند.

### 6.15.7 الموردون والذمم
ملف المورد وشروط الدفع، الفواتير والإشعارات الدائنة/المدينة، الدفعات الجزئية وجدولتها، أعمار الديون، كشف حساب ومطابقة. لا يستخدم مورد تابع لمدرسة أخرى.

### 6.15.8 الأصول والإهلاك
سجل أصل ورقمه وموقعه ومسؤوله وتكلفته وتاريخ وضعه بالخدمة، فئته وعمره الإنتاجي وقيمته المتبقية وطريقة الإهلاك، احتساب دوري، نقل بين مواقع المدرسة، صيانة وبيع أو استبعاد، وقيود الشراء والإهلاك والاستبعاد.

### 6.15.9 الميزانيات ومراكز التكلفة
ميزانية سنوية أو فصلية حسب الحساب والفرع والقسم، اعتماد الميزانية، مقارنة الفعلي بالمخطط، نسب الانحراف والتنبيه، ومراكز تكلفة مثل النقل والمختبر والأنشطة والمراحل.

### 6.15.10 التقارير المالية
- دفتر الأستاذ العام والمساعد وكشف حركة الحساب.
- ميزان المراجعة.
- قائمة الدخل أو الأنشطة.
- المركز المالي/الميزانية العمومية.
- التدفقات النقدية.
- أعمار الذمم المدينة والدائنة.
- حركة الصناديق والبنوك.
- الإيرادات حسب النوع والصف والفرع.
- المصروفات حسب الحساب والقسم ومركز التكلفة.
- مقارنة الميزانية بالفعلي وصافي الفائض أو العجز.
- الضرائب والرسوم إذا كانت مطلوبة.

تدعم التقارير الفلترة حسب الفترة والفرع ومركز التكلفة والحساب، والانتقال من الإجمالي إلى القيود والمستندات المصدرية مع فحص الصلاحية في كل مستوى.

### 6.15.11 الرقابة والإقفال
- فصل منشئ السند عن معتمده ومرحله متى أمكن.
- حدود اعتماد حسب قيمة العملية.
- قفل الفترة بعد المطابقة.
- فتح استثنائي بسبب موثق وسجل تدقيق.
- مراجعة القيود غير المرحلة والمستندات غير المكتملة.
- نسخة احتياطية قبل الإقفال السنوي.
- إقفال الإيرادات والمصروفات وترحيل النتيجة وفق السياسة.
- ترحيل الأرصدة الافتتاحية للسنة التالية مع رابط للمصدر.

## 6.16 الرواتب وشؤون الموظفين المالية
- مكونات الراتب: أساسي وبدلات وحوافز ومكافآت وخصومات.
- تأثير الغياب والتأخير والإضافي والإجازات على الراتب.
- السلف والقروض واستردادها بالأقساط.
- مسير لكل فترة، مراجعة واعتماد، وقسيمة سرية لكل موظف.
- ملف تحويل بنكي أو سند صرف.
- قيود آلية في دفتر المدرسة.
- إقفال المسير ومنع تعديله إلا بتسوية لاحقة.

## 6.17 المشتريات والموردون
طلب شراء من القسم، عروض أسعار، أمر شراء واعتماد حسب القيمة، استلام وفحص، فاتورة مورد، مرتجع مشتريات، ربط بمركز تكلفة وميزانية، إنشاء حركة مخزون أو أصل أو مصروف بحسب الصنف، ثم تكامل الالتزام والدفع مع المحاسبة.

## 6.18 المخزون والمستودعات
مستودعات ومواقع، أصناف ووحدات قياس وأكواد وباركود، تصنيفات وحد إعادة الطلب، أرصدة افتتاحية، استلام وصرف وتحويل وجرد وتسوية، صرف للأقسام والطلاب، تنبيه نفاد، تقييم مخزون وفق طريقة تعتمدها المدرسة، سجل حركة وربط الصرف بمركز تكلفة وقيد عند الترحيل.

## 6.19 المكتبة
الكتب والنسخ والرقم التعريفي والتصنيف والمؤلف والناشر، المستفيدون من طلاب وموظفين، الإعارة والإرجاع والتجديد والحجز، مدد وغرامات حسب السياسة، التالف والمفقود، تنبيهات التأخير وتقارير الكتب الأكثر استعارة. ربط الغرامة بحساب الطالب أو سند مالي من خلال إجراء معتمد.

## 6.20 النقل المدرسي
الحافلات والسعة والحالة، السائقون والمشرفون والوثائق، المسارات والمحطات ومواعيد الالتقاط، تسجيل الطلاب وتوزيعهم، حضور الصعود والنزول، رسوم النقل، الصيانة والوقود والتأمين، تقارير الرحلات والمصروفات. GPS اختياري وصلاحيات الموقع شديدة التقييد.

## 6.21 العيادة المدرسية والسلامة
زيارات وإسعافات أولية وحوادث، تنبيهات حساسية أو معلومات صحية ضرورية فقط، صلاحيات لا تمنح تلقائياً للمعلم، اتصال ولي الأمر، سجل الحوادث والسلامة والإخلاء، صلاحية مستلزمات الإسعاف، وتقارير إحصائية لا تكشف التفاصيل الحساسة.

## 6.22 الأنشطة والرحلات والفعاليات
الأنشطة والنوادي والمسابقات، المشاركون والمشرفون، الرحلات والموافقات، التكاليف والتحصيل، الحضور والملاحظات، شهادات المشاركة وتقويم الفعاليات والإشعارات.

## 6.23 التواصل والإعلانات والمراسلات
إعلانات عامة أو موجهة لفرع أو مرحلة أو صف أو شعبة، رسائل رسمية بين المعلم وولي الأمر، مواعيد مقابلات، قنوات تواصل ذات سجل، رسائل جماعية بموافقات وحدود إرسال، قوالب ومرفقات. يمكن للمدرسة تعطيل المحادثات المباشرة والاكتفاء بالقنوات الرسمية.

## 6.24 الإشعارات والتنبيهات
**القنوات:** داخل النظام، Push، البريد، SMS، WhatsApp عبر موصل API قابل للتبديل.

**الأحداث:** القبول والرفض والتسجيل والنقل، الغياب والتأخر، الواجب وموعد التسليم والتصحيح، نشر الدرجات والشهادات، الفواتير والأقساط والدفعات والمتأخرات، تغيير الجدول وإلغاء الحصة والمعلم البديل، الإعلانات والفعاليات والرحلات، الموافقات والاجتماعات والتنبيهات الإدارية.

**القواعد:** لكل مدرسة قوالبها وقنواتها؛ المستلم يحدد من الحدث والعلاقة والصلاحية؛ لا ترسل درجة أو مبلغاً لولي أمر غير مخول؛ تفضيلات لكل مستخدم ونوع وقناة ووقت هدوء؛ منع التكرار بمفتاح idempotency؛ طابور وإعادة محاولة؛ حفظ الحالة (منتظر، أرسل، وصل، قرئ إن توفر، فشل، ألغي)؛ سجل التسليم مستقل عن الحدث؛ احترام الموافقات وسياسات الرسائل.

## 6.25 المستندات والأرشفة
مستودع ملفات خاص بكل مدرسة، تصنيفات وصلاحيات، ملفات الطالب والموظف والعقد والفاتورة والاختبار والشهادة، نسخ متعددة، تاريخ انتهاء الوثائق، روابط مؤقتة، فحص نوع الملف وحجمه ومحتواه، سجل اطلاع وتنزيل للوثائق الحساسة، وسياسات احتفاظ وأرشفة.

## 6.26 التقارير ولوحات المعلومات
- **المدير:** أعداد الطلاب والقبول والحضور والتحصيل والمتأخرات والنتائج والفروع والتنبيهات.
- **المعلم:** حصص اليوم والطلاب والحضور والواجبات المطلوب تصحيحها والاختبارات والرسائل.
- **المحاسب:** المقبوضات والمدفوعات والصناديق والذمم والقيود غير المرحلة والفترات والتقارير المالية.
- **ولي الأمر:** حالة الأبناء والحضور والواجبات والنتائج المنشورة والمستحقات والإشعارات.
- **الطالب:** الجدول والواجبات والمواد والدرجات المنشورة والإعلانات.

تدعم التقارير الفلترة حسب الفترة والفرع والصف والشعبة والمادة والحالة، وتصدير PDF/Excel حسب الصلاحية، وتعرض وقت الإنشاء ومصدر البيانات. التقارير الكبيرة تنفذ بالخلفية ويصل إشعار عند اكتمالها.

## 6.27 الاستبيانات والتقييم الداخلي
قوالب وأسئلة وأنواع إجابة، جمهور وفترة إتاحة، إخفاء هوية عند الحاجة، تحليل وإحصاءات وإعدادات خصوصية وموافقات.

## 6.28 بوابة المدرسة العامة
موقع تعريفي اختياري للأخبار والنبذة والمراحل وشروط القبول ونموذج التقديم وبيانات الاتصال والتقويم العام. يفصل كلياً عن بيانات الطلاب والبوابات الخاصة.

# 7. الأدوار والصلاحيات

## 7.1 النموذج العام
تعتمد المنصة RBAC مع صلاحيات دقيقة (Permission-Based Access Control)، ويمكن إضافة قيود سياقية حسب الفرع والسجل والقيمة والحالة. الأدوار قوالب لتجميع الصلاحيات وليست بديلاً عن التحقق من كل عملية.

تتكون الصلاحية من **المورد + الفعل + النطاق**، مثل `students.view` ضمن المدرسة أو الفرع، و`grades.enter` و`grades.approve` و`grades.publish`، و`finance.receipt.create` و`finance.receipt.post` و`finance.refund.approve`، و`accounting.journal.create` و`accounting.journal.post` و`accounting.period.close`.

## 7.2 الأدوار الافتراضية
مالك المنصة، مسؤول عمليات المنصة، دعم فني مؤقت محدود، مالك المدرسة/المدير العام، مدير المدرسة، نائب المدير، مدير الفرع، القبول والتسجيل، شؤون الطلاب، رئيس قسم أكاديمي، معلم، معلم بديل، مراقب اختبار، مسؤول الكنترول، محاسب، أمين صندوق، مدير مالي، موارد بشرية، مشتريات، أمين مستودع، أمين مكتبة، مسؤول نقل، مرشد طلابي، مسؤول عيادة، مسؤول اتصال وإشعارات، ولي أمر، طالب، مدقق داخلي للقراءة فقط.

## 7.3 خصائص إلزامية
- صلاحيات على مستوى المدرسة والفرع.
- نطاق صفوف وشعب ومواد للمعلم.
- تقييد الحقول الحساسة لا الصفحات فقط.
- فصل العرض والإنشاء والتعديل والاعتماد والترحيل والنشر والأرشفة والتصدير.
- حدود مالية حسب القيمة.
- تفويض مؤقت بتاريخ بداية ونهاية.
- منع اعتماد المستخدم عملية أنشأها بنفسه في العمليات عالية المخاطر متى تطلبت سياسة المدرسة الفصل.
- سجل تغييرات الدور والصلاحيات وإبطال الجلسات عند سحب صلاحية حساسة.

لا تمنح كل الصلاحيات للمدير دون إعداد واضح. يجب أن يكون هناك حساب مالك طوارئ محمي ومراقب.

# 8. تطبيق Expo + React Native الموحد

## 8.1 الدخول واختيار المدرسة
- الدخول برقم هاتف أو بريد بحسب سياسة الهوية والتحقق.
- استعادة الحساب والتحقق متعدد الخطوات عند الحاجة.
- بعد الدخول يجلب التطبيق المدارس والعضويات المصرح بها.
- مدرسة واحدة: دخول مباشر؛ عدة مدارس: شاشة اختيار.
- تبديل المدرسة يغير السياق ويمسح البيانات المؤقتة الخاصة بالشاشة السابقة.
- كود المدرسة يساعد على العثور عليها أو طلب الانضمام، ولا يمنح الوصول بذاته.

## 8.2 تجربة كل دور
المعلم: جدول يومي، فتح الحصة، حضور، واجبات، درجات، رسائل ومواد. ولي الأمر: بطاقات الأبناء والتبديل بينهم والحضور والواجبات والنتائج المنشورة والرسوم والإشعارات. الطالب: جدول وواجبات وتسليم ونتائج منشورة وإعلانات. الإدارة: ملخصات وموافقات وإجراءات سريعة.

الواجهة عربية RTL افتراضياً، متجاوبة وتدعم أحجام الخط وإمكانية الوصول. لا تظهر قوائم لا يحتاجها الدور.

## 8.3 العمل دون اتصال
يمكن تخزين بيانات قراءة محدودة مثل الجدول للعرض دون اتصال. لا يسمح بترحيل مالي أو تعديل حساس دون اتصال. يمكن وضع الحضور في قائمة انتظار مشفرة ثم مزامنته مع كشف التعارضات وإظهار نتيجة المزامنة. لا يفترض التطبيق نجاح العملية قبل تأكيد الخادم.

# 10. API والتكاملات

## 10.1 قواعد API
- بادئة الإصدار `/api/v1/`.
- JSON موحد وأخطاء واضحة ورمز تتبع للطلب.
- ترقيم صفحات وفلاتر وترتيب معلن.
- إرجاع أقل قدر تحتاجه الشاشة.
- صلاحيات على كل endpoint وكل سجل.
- توثيق OpenAPI محدث.
- عمليات الأثر الجانبي عبر حالات استخدام واضحة، لا تعديلات جداول مباشرة.
- مفاتيح idempotency للدفعات والترحيل والإشعارات.
- عدم كشف معرفات داخلية يمكن تخمينها دون تحقق صلاحية.

# 11. الأمان والخصوصية والاعتمادية

## 11.1 المصادقة والجلسات
- تجزئة كلمات المرور بخوارزمية قوية مدعومة من Django.
- التحقق من البريد أو الهاتف وفق مسار موثق.
- مصادقة متعددة العوامل للحسابات الحساسة.
- حدود محاولات الدخول ومكافحة التخمين.
- JWT قصير العمر وRefresh Token آمن أو جلسات ويب محمية.
- إبطال الجلسات عند تعطيل العضوية أو تغيير بيانات الاعتماد الحساسة.
- تخزين رموز الهاتف في مساحة آمنة.

## 11.2 البيانات الحساسة
أقل قدر ممكن من البيانات الصحية والشخصية، HTTPS دائماً، تشفير النسخ الاحتياطية والملفات الحساسة، إخفاء أرقام الهاتف والوثائق في السجلات، صلاحية مستقلة للحقول الحساسة، وتوثيق سبب الاطلاع عند الحاجة. تحدد سياسة الاحتفاظ والحذف بحسب المتطلبات القانونية لبلد المدرسة.

## 11.3 سجل التدقيق
يسجل إنشاء وتعديل وأرشفة السجلات الحساسة، تعديل الدرجات والحضور المعتمد، الرسوم والخصومات والمنح، إنشاء واعتماد وترحيل وعكس السندات والقيود، فتح وإغلاق الفترات، تغيير الصلاحيات، تنزيل الملفات وتصدير التقارير، وجلسات الدعم.

يحوي الحدث المستخدم والمدرسة والوقت والفعل والكيان ومعرفه والقيم المتغيرة والسبب وIP أو معرف الجهاز عند ملاءمته. يحظر تخزين كلمات المرور والرموز والأسرار في سجل التدقيق.

## 11.4 النسخ الاحتياطي والتعافي
- نسخ قاعدة البيانات والملفات آلياً بجدول معلوم.
- تخزين نسخ مشفرة خارج الخادم الأساسي.
- اختبار استعادة دوري؛ النسخة غير المختبرة لا تعتبر خطة تعافٍ.
- تحديد RPO وRTO قبل الإنتاج.
- استعادة مدرسة منفردة من قاعدة مشتركة تتطلب إجراءً مدروساً: استعادة إلى بيئة مؤقتة ثم استخراج نطاقها مع فحص العلاقات، أو تخصيص استراتيجية فصل للمدارس الكبيرة.
- سجل لنتائج النسخ والتنبيهات عند الفشل.

## 11.5 الأداء والتوسع
فهارس مركبة تبدأ غالباً بـ `school_id` ثم التاريخ أو الحالة، تجنب N+1، مفاتيح cache تتضمن المدرسة والدور والسياق، التقارير والاستيراد والإشعارات في الخلفية، حدود API والتصدير، مراقبة زمن الاستجابة والمهام وحجم البيانات. يمكن تقسيم الجداول الكبيرة أو نقل مدرسة كبيرة إلى قاعدة منفصلة عند الحاجة.

# 12. الاختبارات وضمان الجودة

## 12.1 اختبارات عزل المدارس (حرجة)
- مستخدم A لا يقرأ طالب B بمعرف مباشر.
- لا يعدل أو يحذف أو يؤرشف سجلات مدرسة أخرى.
- لا ينزل مرفقات أو تقارير مدرسة أخرى.
- لا يدرج قيداً أو طالباً مع `school_id` غير مصرح به.
- cache وexports وbackground tasks لا تتجاوز العزل.
- ولي الأمر لا يرى طالباً غير مرتبط به.
- المعلم لا يرى شعباً أو درجات غير مسندة إليه.

## 12.2 اختبارات المحاسبة
توازن كل قيد مرحل، رفض غير المتوازن، رفض حساب من مدرسة أخرى، رفض الترحيل في فترة مغلقة، عدم تكرار القيد عند إعادة الطلب، منع تعديل وحذف المرحل، صحة العكس والتسويات، تطابق الأستاذ وميزان المراجعة، صحة ربط القبض بالذمم والصندوق، واختبار الإقفال والافتتاح.

## 12.3 اختبارات الجدول والأكاديميا
منع تعارض المعلم والشعبة والغرفة، والتحقق من النصاب وعدد الحصص، حفظ نسخ الجدول المنشورة، حساب الدرجات بالأوزان، منع نشر النتائج قبل الاعتماد، عدم احتساب الحصة الملغاة غياباً، عدم تكرار حضور الحصة، وحفظ محاولات الواجب.

## 12.4 مستويات الاختبار
Unit tests، Integration tests، API tests، Contract tests بين API والواجهتين، E2E، اختبارات تحميل، أمان، استعادة النسخ الاحتياطية، وتجربة الاستخدام على الهاتف.

# 13. واجهات الإدارة وتجربة الويب

- واجهة عربية RTL أولاً وخط واضح وتباين قوي.
- تجربة تشبه تطبيقاً إدارياً لا موقعاً مزدحماً.
- قائمة موحدة قابلة للطي وتظهر الوحدات المفعلة والمسموحة فقط.
- صفحات مستقلة للوحدات، مع بطاقات ملخص وإحصاءات وجداول واضحة.
- البحث والفرز والتصفية داخل الصفحة.
- نماذج الإضافة والتعديل تفتح عند الطلب ولا تزاحم الشاشة افتراضياً.
- تفاصيل السجل في صفحة أو درج واضح، مع سجل نشاط وأفعال حسب الصلاحية.
- تأكيد للعمليات الحساسة وعرض أثر العملية قبل اعتمادها.
- حالات تحميل وفراغ وخطأ واضحة، وعدم إخفاء فشل الحفظ.
- حفظ المرشحات عند الرجوع حيث يكون ذلك مفيداً.

تتغير لوحة المدرسة حسب الدور. يمكن تخصيص ترتيب البطاقات دون تغيير صلاحيات الوصول. كل وحدة توفر حسب طبيعتها: ملخصاً، قائمة قابلة للبحث والفرز، تفاصيل، إضافة وتعديل، حالات وإجراءات، أرشيفاً، استيراداً/تصديراً، مؤشرات، وسجل تدقيق للسجلات الحساسة.

# 14. سير العمل المتكامل بين الوحدات

## 14.1 تسجيل طالب
طلب تقديم ← مراجعة وثائق ← قبول ← إنشاء ملف ← ربط ولي الأمر ← تسجيل في سنة وصف وشعبة ← تطبيق هيكل الرسوم ← إنشاء فاتورة وأقساط ← إشعار القبول ← تحديث الإحصاءات.

## 14.2 تحصيل قسط
اختيار الطالب والاستحقاق ← مبلغ وطريقة دفع وصندوق ← التحقق والتخصيص ← اعتماد/ترحيل سند القبض ← تحديث حساب الطالب ← قيد في دفتر المدرسة ← إيصال ← إشعار ولي الأمر ← تحديث التقارير.

إذا فشل إنشاء القيد، لا تعلن العملية المالية مكتملة بصمت. يحفظ الحدث في Outbox ويعاد معالجته، وتظهر حالة مطابقة واضحة للمحاسب.

## 14.3 تنفيذ حصة
فتح الجدول ← اختيار الحصة المسندة ← عرض الشعبة ← تسجيل الحضور ← تسجيل موضوع الدرس ← إضافة مادة أو واجب ← حفظ سجل الحصة ← إرسال الإشعارات.

## 14.4 نشر النتائج
إدخال درجات ← تحقق الحدود ← مراجعة القسم/الكنترول ← اعتماد ← قفل دفتر الدرجات ← نشر ← إشعار ولي الأمر والطالب ← توليد كشف بدرجات ونسخة سياسة التقييم.

## 14.5 دورة الرواتب
تجهيز الحضور ← إعداد المسير ← احتساب السلف والخصومات ← مراجعة الموارد البشرية ← اعتماد مالي ← قيد الرواتب ← الصرف ← قسائم الرواتب ← الإقفال.

## 14.6 المشتريات والمخزون
طلب شراء ← اعتماد ← عروض أسعار ← أمر شراء ← استلام وفحص ← إدخال مخزون/أصل ← فاتورة مورد ← إثبات التزام ← سداد ← مطابقة وإغلاق.

# 17. مراحل التنفيذ

لا تبنَ الوحدات كلها بالتوازي. ينفذ كل طور Backend وWeb واختبارات وتوثيقاً، ثم يرفع ويراجع قبل الانتقال.

1. **التأسيس والحوكمة:** المستودع والهيكل والبيئات وCI وPostgreSQL وRedis والملفات وقرارات المعمارية ووثائق التشغيل. الخروج: تشغيل محلي قابل للتكرار وفحص آلي ناجح.
2. **المنصة والمستأجرون والهوية:** المدارس والأكواد والحالات والمستخدمون والعضويات والدعوات وسياق المدرسة والأدوار والصلاحيات. الخروج: اختبار عزل ناجح بين مدرستين، وإمكان عضوية المستخدم في عدة مدارس.
3. **إعداد المدرسة والهيكل الأكاديمي:** الفروع والغرف والسنوات والفصول والتقويم والمراحل والصفوف والشعب والمواد والمعلمون. الخروج: تهيئة مدرستين بإعدادات مستقلة.
4. **القبول والطلاب وأولياء الأمور:** الطلبات والملفات والتسجيلات السنوية والعلاقات والدعوات والاستيراد والأرشفة. الخروج: تسجيل وربط ولي أمر آمن.
5. **الجدول والحصص:** قوالب وأيام وجداول وكشف تعارض وإصدارات واعتماد ونشر. الخروج: رفض تعارض معلم أو شعبة أو غرفة.
6. **الحضور والدروس والواجبات:** الحضور والأعذار والخطط وسجل الدروس والواجبات والتسليم والتصحيح. الخروج: معلم ينفذ حصته ضمن نطاقه فقط.
7. **الاختبارات والدرجات:** سياسات تقييم واختبارات وكنترول واعتماد ونشر وشهادات. الخروج: نتائج قابلة لإعادة التحقق وأدوار منفصلة للإدخال والاعتماد والنشر.
8. **الرسوم والتحصيل:** هياكل وأقساط وفواتير وخصومات ومنح وسندات وتوزيع دفعات واسترداد وكشوف. الخروج: رصيد الطالب والتحصيل مطابقان.
9. **المحاسبة:** الدليل والفترات والقيود والصناديق وتكامل الرسوم والأستاذ والميزان والقوائم والموردون والميزانيات والأصول والإقفال. الخروج: دفتر مستقل لكل مدرسة وقيود متوازنة.
10. **الموارد والمشتريات والمخزون:** الموظفون والعقود والرواتب والموردون والمشتريات والمستودعات والتكامل المحاسبي.
11. **الخدمات الاختيارية:** المكتبة والنقل والعيادة والأنشطة، كل منها بميزة مستقلة.
12. **الإشعارات وExpo + React Native:** مركز القوالب والتسليم والموصلات والتطبيق الموحد حسب الأدوار والمزامنة المحدودة.
13. **الإطلاق:** اختبارات الأمان والتحميل والاستعادة والاستيراد التجريبي ودليل المستخدم والمراقبة وتجربة مدرسة تجريبية.

# 18. معيار اكتمال الوحدة (Definition of Done)

لا تعد الوحدة مكتملة بمجرد ظهور صفحة أو حفظ سجل. يجب أن تتضمن:
1. نطاقاً ومسؤولية واضحين.
2. نماذج وعلاقات وقيوداً وفهارس.
3. migrations قابلة للتطبيق.
4. خدمات أعمال منفصلة عن العرض.
5. API موثقاً ومختبراً.
6. صلاحيات على الفعل والسجل والمدرسة.
7. عزل مدرسة واختبارات سلبية.
8. واجهة متجاوبة وحالات فراغ وتحميل وخطأ.
9. بحثاً وفلاتر وفرزاً وترقيماً مناسباً.
10. تدقيقاً للعمليات الحساسة.
11. إشعارات عند الحاجة.
12. تقارير وتصديراً عند الحاجة.
13. اختبارات وحدات وتكامل وواجهة.
14. توثيق الاستخدام والإعداد والتشغيل.
15. عدم وجود أخطاء حرجة أو بيانات تجريبية في الإنتاج.

# 19. قرارات يجب تثبيتها أثناء التحليل التفصيلي

- نظام الدرجات والتقويم الدراسي لكل بلد أو مدرسة.
- عدد الفصول الأكاديمية وسياسة النجاح والتقريب والإعادة.
- العملة الأساسية وتعدد العملات وأسعار الصرف.
- أساس الاعتراف المحاسبي بالإيرادات والمصروفات.
- الضرائب والرسوم النظامية إن وجدت.
- ترقيم الطلاب والفواتير والقيود.
- سياسات الغياب والخصومات والإعفاءات.
- مدد الاحتفاظ ببيانات الطلاب والموظفين والملفات.
- القنوات المسموحة لإشعارات أولياء الأمور.
- قواعد خصوصية القاصرين والموافقات.
- الباقات وحدود الاستخدام والأسعار.

تُمثل هذه السياسات كإعدادات موثقة وإصدارات مؤرخة، لا كثوابت مبعثرة في الكود.

# 21. استراتيجية الإطلاق والبيانات الأولية

- لا ترفع بيانات مدارس حقيقية قبل نجاح اختبارات العزل.
- ابدأ بمدرسة تجريبية وبيانات اصطناعية.
- اختبر سنة أكاديمية كاملة من التسجيل حتى النتائج والترحيل.
- اختبر دورة مالية من الاستحقاق حتى التحصيل والتقرير والإقفال.
- استورد الطلاب وأولياء الأمور بملف معاينة لا بإدخال غير قابل للتراجع.
- طابق الأرصدة الافتتاحية مع المحاسب قبل تشغيل الدفتر.
- احتفظ بنسخة من الإعدادات قبل أي استيراد كبير.
- جهز خطة رجوع عند فشل النشر أو ترحيل البيانات.

# 22. الخلاصة التنفيذية

School منصة متعددة المدارس، لكن استقلال المدرسة هو محور التصميم: لكل مدرسة هويتها ومستخدميها وفروعها وسنواتها الأكاديمية وطلابها ومعلموها وجداولها وحصصها وواجباتها ودرجاتها وملفاتها وإشعاراتها، والأهم **دفترها المحاسبي الخاص الذي لا يختلط مع دفتر أي مدرسة أخرى**.

يبدأ التنفيذ بتثبيت المستأجرين والهوية والصلاحيات وقواعد البيانات، ثم المجال الأكاديمي، ثم العمليات اليومية، ثم الرسوم والدفاتر المحاسبية، ثم الخدمات الاختيارية والتطبيق المحمول. أي ميزة لا تحترم عزل المدرسة أو التاريخ أو التدقيق لا تعتبر مكتملة.

**معيار النجاح النهائي:** يدير مشغل المنصة مدارس عديدة من حساب مركزي، بينما تعمل كل مدرسة كما لو أنها تمتلك نظاماً مستقلاً، فلا ترى أو تؤثر في بيانات مدرسة أخرى ولا تختلط حساباتها ونتائجها وعملياتها.

## قواعد الاعتماد
1. `tenants` و`identity` و`authorization` طبقات تأسيسية.
2. `students` و`staff` و`organization` و`academic_calendar` لا تعتمد على واجهات الوحدات العليا.
3. `timetable` يعتمد على الهيكل الأكاديمي وتعيينات الموظفين، ولا يملك بياناتهم الأساسية.
4. `attendance` يعتمد على الطلاب والدروس المجدولة، لكنه يملك سجلات الحضور.
5. `assignments` و`assessments` يملكان عملياتهما؛ `results` يملك النشر النهائي.
6. `student_fees` يملك الذمم التجارية، و`accounting` يملك الدفتر العام. التكامل عبر خدمة ترحيل محاسبي ومرجع فريد.
7. `payroll` و`procurement` و`inventory` و`assets` ترسل المستندات المعتمدة إلى المحاسبة عبر عقود واضحة.
8. `notifications` تستقبل أحداثاً تجارية أو طلب إشعار مصرحاً به.
9. `reports` للقراءة فقط من منظور الأعمال.
10. `audit_log` يستقبل الأحداث ولا يستخدم مخزناً بديلاً لبيانات الوحدات.

## نمط التكامل
- العمليات التي يجب أن تنجح معاً تستخدم خدمة تطبيقية ومعاملة قاعدة بيانات واحدة.
- الآثار اللاحقة مثل الإشعار والتقرير تستخدم Transactional Outbox ثم Celery.
- كل حدث يحمل معرفاً فريداً والمدرسة والكيان ومرجع المصدر ووقت الحدث وإصدار المخطط.
- كل مستهلك idempotent حتى لا يكرر القيد أو الإشعار عند إعادة المحاولة.

# ملحق: 03 قواعد البيانات والعزل

# قواعد تصميم قاعدة البيانات وعزل المدارس

## 1. ملكية البيانات
كل سجل تشغيلي أنشأته مدرسة أو يخص عملياتها يحمل `school_id` مباشرة. لا تعتمد الملكية على المرور عبر سلسلة علاقات فقط. يضاف `branch_id` و`academic_year_id` عند انطباقهما.

## 2. المفاتيح الفريدة
الأكواد التي يختارها المستخدم فريدة داخل المدرسة، مثل رقم الطالب والموظف وكود المادة والحساب ورقم الفاتورة والسند والقيد والغرفة والحافلة. تستخدم قيود مثل `UNIQUE(school_id, code)` أو `UNIQUE(school_id, fiscal_year_id, document_type, sequence)`.

## 3. منع العلاقات العابرة
لا يكفي أن يكون `student_id` صحيحاً. يجب التحقق أن الطالب والفاتورة والحساب والفرع من المدرسة نفسها. مثال: يجب أن يتطابق `journal_line.school_id` و`journal_entry.school_id` و`account.school_id`. استخدم قيوداً مركبة أو تحققاً خدمياً مدعوماً بقيود قاعدة البيانات حيثما أمكن.

## 4. فصل المنصة عن المدرسة
بيانات المدارس والاشتراكات والدعم مركزية، وبيانات العمليات اليومية مملوكة للمدرسة. لا تخلط فاتورة اشتراك المنصة بفاتورة رسوم طالب؛ لكل مجال خدمة وواجهات ونطاق بيانات.

## 5. الأرشفة والحذف
- أرشفة الطالب أو الموظف لا تمحو سنواته السابقة.
- لا تحذف سنة دراسية عليها سجلات.
- لا تحذف حساباً محاسبياً مستخدماً في قيد؛ يعطل فقط.
- لا تحذف قيداً أو سنداً مرحلاً.
- يمكن إبطال الوصول إلى ملف دون كسر مرجع التدقيق.
- الأرشيف قابل للبحث والاستعادة بصلاحية وسبب مسجلين.

## 6. التاريخ
- الالتحاق مرتبط بسنة دراسية.
- الجدول يحتفظ بإصدارات وتواريخ سريان.
- سياسة التقييم تحفظ نسختها عند اعتماد النتائج.
- التعديل التاريخي لا يعيد الحساب تلقائياً دون إجراء صريح.
- تخزن الطوابع الزمنية بشكل موحد وتعرض حسب المنطقة الزمنية للمدرسة.

## 7. الدقة الرقمية والمالية
- استخدم Decimal للمبالغ والدرجات التي تحتاج كسوراً.
- العملة تحدد المنازل العشرية وسياسة التقريب.
- كل قيد يحتفظ بالعملة الوظيفية؛ العملة الأجنبية تتطلب مبلغاً أصلياً وسعر صرف وتاريخه.
- لا تستخدم float للأموال.
- احتفظ بتفاصيل أسطر الفاتورة والخصم والضريبة ومصدر المبلغ.

## 8. الملفات
- الملفات خارج مسارات النشر العامة.
- المسار المنطقي يتضمن معرف المدرسة والوحدة والكيان.
- لا يعتمد اسم الملف الفعلي على الاسم المرفوع وحده.
- فحص الامتداد والحجم ونوع المحتوى.
- لا رابط عام لملف خاص.
- تنزيل الملف يعيد فحص صلاحية المستخدم وعلاقته بالمدرسة والسجل.

## 9. الفهارس
تراجع وفق الاستعلامات الفعلية، ومن أمثلتها: `(school_id, status, created_at)` للقوائم، `(school_id, academic_year_id, grade_level_id, section_id)` للطلاب، `(school_id, student_id, date)` للحضور، `(school_id, fiscal_year_id, entry_date, status)` للقيود، و`(school_id, account_id, entry_date)` للأستاذ.

## 10. اختبار العزل شرط دمج
لكل endpoint وخدمة ومهمة خلفية: طلب المدرسة نفسها ينجح، ومدرسة أخرى تفشل، ومستخدم بلا عضوية يفشل، ومعرف المدرسة المزور لا يغير السياق، وسجل من مدرسة مختلفة يرفض، والتصدير والملفات والتقارير لا تتجاوز العزل.

1. إثبات عزل مدرستين آلياً.
2. تسجيل طالب من القبول حتى الجدول.
3. حضور حصة وإضافة واجب وتسليمه وتصحيحه.
4. إدخال درجات واعتمادها ونشرها.

7. ميزان مراجعة لا يتضمن أرصدة مدرسة أخرى.
8. نجاح النسخ الاحتياطي والاستعادة.
