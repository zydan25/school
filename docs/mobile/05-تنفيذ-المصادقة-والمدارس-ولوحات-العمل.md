# تقرير تنفيذ المصادقة والمدارس ولوحات العمل

**المشروع:** School Mobile  
**الفرع:** feature/mobile-expo-foundation  
**النطاق:** نقل التطبيق من معرض تصميم فقط إلى عميل موبايل متصل بعقود المصادقة والمدارس والملفات واللوحات الأولية في School API.

## 1. المصادقة والحساب
تمت إضافة:
- تسجيل الدخول بالهاتف وكلمة المرور إلى POST /api/v1/auth/login/.
- إرسال معرف جهاز ثابت في X-Device-ID وبيانات الجهاز.
- التسجيل إلى POST /api/v1/auth/register/.
- تأكيد رقم الهاتف إلى POST /api/v1/auth/phone/verify/ وإعادة إرسال الرمز إلى POST /api/v1/auth/phone/resend/.
- طلب وإتمام استعادة كلمة المرور إلى مساري auth/password/reset/request/ وauth/password/reset/confirm/.
- تجديد الجلسة إلى auth/sessions/refresh/ وإبطال الجلسة الحالية إلى auth/logout/.

تُحفظ الجلسة ومعرف الجهاز في Expo SecureStore. كلمة المرور لا تحفظ محلياً. يتم تجديد access token عند قرب انتهائه أو عند استجابة 401، ويعاد الطلب مرة واحدة فقط. وعند انتهاء الجلسة نهائياً، تزال بيانات الجلسة والـ Query Cache الخاص بها.

## 2. المدارس والدعوات
- يجلب التطبيق ملف المستخدم من GET /api/v1/me/ والمدارس من GET /api/v1/schools/.
- يحترم مدرسة الحساب الافتراضية عند وجود مدرسة افتراضية وحيدة؛ وإلا يتيح الاختيار اليدوي.
- يدعم قبول دعوة المدرسة من POST /api/v1/app/account/invitations/accept/، ثم يحدّث قائمة المدارس والأدوار من استجابة الخادم.
- لا يضيف التطبيق عضويات محلياً ولا يثق برقم مدرسة يكتبه المستخدم.

## 3. مساحات العمل والملفات
- يجلب الملفات من GET /api/v1/app/account/profiles/.
- يعرض الدور فقط عندما يتطابق مع عضوية المدرسة وملف الحساب المسموح.
- يدعم مساحات الطالب وولي الأمر والمعلم والموظف والإدارة.
- عند وجود أكثر من ملف من النوع نفسه، تنبه الشاشة إلى أن المسارات الحالية في الخادم تختار الملف النشط الأول؛ لم نخترع مساراً غير موجود لتبديل الملف.

## 4. اللوحات المتصلة بالبيانات
| المساحة | مصادر البيانات |
|---|---|
| ولي الأمر | app/my/children/ وapp/my/timetable/?profile_type=guardian |
| الطالب | students/ وapp/my/timetable/?profile_type=student |
| المعلم | app/teacher-assignments/ وstudents/ وapp/my/timetable/?profile_type=teacher |
| الموظف | app/account/profiles/ |
| الإدارة | تحقق من دور الإدارة والملفات؛ وحدات الإدارة التفصيلية لم تُنفذ بعد |

لوحة ولي الأمر تتيح اختيار الابن لعرض ملفه، ويظهر الجدول بصيغة مجمعة لجداول الأبناء لأن عقد الخادم الحالي يعيد الجداول للملفات المرتبطة معاً. لوحة المعلم تعرض الإسنادات والشعب والطلاب العائدين من API. لا تعرض اللوحات أرقاماً تجريبية في التشغيل الحقيقي.

## 5. عزل المدارس والحسابات
- كل طلب مدرسي يستخدم Bearer وX-School-ID.
- مفاتيح Query Cache تتضمن user ID وsession ID وschool ID والدور.
- يتم مسح الذاكرة المؤقتة عند تسجيل الخروج أو تبديل المدرسة أو الدور أو تغيير الحساب.
- 401 يؤدي إلى محاولة تجديد واحدة؛ أما الأخطاء الأخرى فتعرض رسالة واضحة وإعادة محاولة.
- أخطاء 403/404 من مسار الجدول وحده تُعامل كعدم توفر جدول للدور، حتى تبقى بيانات الملف والإسناد مرئية بدلاً من إخفائها.

## 6. ملفات رئيسية
- mobile/src/core/auth/: الجلسة والتخزين الآمن وحالة المصادقة.
- mobile/src/core/api/: العميل العام وطلبات API الموثقة.
- mobile/src/features/auth/: الدخول والتسجيل وOTP واستعادة كلمة المرور.
- mobile/src/features/schools/: اختيار المدرسة وقبول الدعوة.
- mobile/src/features/profiles/: تحميل الملفات واختيار مساحة العمل.
- mobile/src/features/dashboard/: مصادر البيانات واللوحات الفعلية.
- mobile/app/: مسارات Expo Router.

## 7. ما لم ينجز في هذه الدفعة
- لم تُربط عمليات الحضور ورصد الغياب، الواجبات وتسليمها، التقييم والدرجات، الرسوم والمدفوعات، المحادثات والإشعارات الفعلية.
- لوحة الإدارة والموظف حالياً أساس هوية وملف وليست بديلاً عن جميع وظائف لوحة الإدارة.
- لا يوجد مسار مستقل لطلب ولي الأمر ربط طفل بنفسه؛ لم نضف هذا السلوك حمايةً لعلاقات الطلاب.
- ملفات متعددة من النوع نفسه لا يمكن اختيارها بمعرف مستقل ما دام عقد الخادم لا يوفر هذا الاختيار.
- لم تُنفذ تجربة E2E بحساب مستخدم إنتاجي، ولم ينشأ APK أو يتم اختباره على هاتف حقيقي في هذه المرحلة.
