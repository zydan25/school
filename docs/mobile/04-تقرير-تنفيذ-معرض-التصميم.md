# تقرير تنفيذ المرحلة التالية: معرض التصميم التفاعلي

**المشروع:** School Mobile
**الفرع:** feature/mobile-expo-foundation
**النطاق:** إكمال نظام العرض المرئي ولوحات الطالب وولي الأمر والمعلم، دون بدء المصادقة أو توصيل بيانات الأعمال.

## ما تم تنفيذه
1. فصل لوحات ولي الأمر والمعلم والطالب إلى مكونات مستقلة.
2. فصل بيانات المعاينة عن مكونات العرض في ملف بيانات مستقل.
3. بناء مكونات مشتركة: AppCard وAppAvatar وAppActionTile وAppStatCard وAppSectionHeader وAppEmptyState وAppNotice وAppIcon.
4. إضافة اختيار الابن، ويتغير ملخص الحضور والواجبات والرسوم بحسب الابن المحدد.
5. إضافة اختيار الشعبة، وتتغير عينة الطلاب المعروضة بحسب الشعبة.
6. إضافة حالات فارغة لولي الأمر الذي لم تربط به ملفات أبناء، وللمعلم الذي لم تسند إليه شعب.
7. جعل اختصارات الخدمات والإشعارات تُظهر رسالة صريحة بأن الشاشة معاينة وليست عملية متصلة بالخادم.
8. إضافة دعم SafeAreaProvider وضبط اتجاه RTL على جذر التطبيق، واستخدام الصفوف المنطقية flexDirection=row بدلاً من مزج RTL مع row-reverse.
9. تحسين شبكة البطاقات بحيث تتكيف مع عرض الهاتف المتاح.
10. توحيد ألوان حالات الواجهة والتدرجات والخلفيات في palette داخل tokens.ts لتسهيل تخصيص الهوية البصرية لاحقاً من الخادم.
11. تحديث معرض التصميم والوثائق البصرية ومواصفات الشاشات.
12. إضافة فحص Android JavaScript bundle إلى Mobile CI، وإضافة concurrency لإلغاء التشغيلات القديمة المتجاوزة.

## حدود المرحلة
- البيانات المعروضة ثابتة وتجريبية ولا تمثل بيانات مدرسة حقيقية.
- لا توجد مصادقة حقيقية أو جلسة مستخدم في هذه المرحلة.
- لا ينشئ زر إضافة ابن علاقة أسرية؛ هو معاينة فقط إلى حين وجود API طلب ربط موثوق واعتماد المدرسة.
- لا يتم إنشاء واجبات أو اعتماد حضور أو حفظ درجات من المعرض.
- لم يتم اعتماد المطابقة النهائية على جهاز Android فعلي بعد؛ يلزم التقاط لقطات شاشة فعلية ومقارنتها بالمرجع البصري قبل اعتماد التصميم للإنتاج.
- لم يتم تنفيذ APK أو ربط حساب EAS.

## معيار قبول المرحلة
- ظهور المعرض عند فتح التطبيق.
- التبديل بين الأدوار الثلاثة.
- اختيار ابن وتحديث الملخص.
- اختيار شعبة وتحديث الطلاب.
- ظهور حالة فارغة صحيحة لولي الأمر والمعلم.
- عدم وجود أزرار شكلية لا تنفذ تفاعلاً أو لا توضح أنها معاينة.
- نجاح فحص Expo TypeScript والتصدير دون أخطاء للالتزام النهائي.
