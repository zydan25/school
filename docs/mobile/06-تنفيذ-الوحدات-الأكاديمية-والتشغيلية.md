# تنفيذ الوحدات الأكاديمية والتشغيلية

**المشروع:** School Mobile  
**الفرع:** feature/mobile-expo-foundation  
**النطاق:** ربط وحدات الاستخدام اليومي بالعقود الموجودة في School API، دون تكرار قواعد الأعمال في الهاتف.

## 1. إعادة استخدام الأكاديميات الموجودة
كانت شاشة الدراسة والتقييم موجودة مسبقاً في:
- mobile/app/academics.tsx
- mobile/src/features/academics/screens/academics-screen.tsx
- mobile/src/features/academics/api/academics-api.ts

أُبقي هذا التنفيذ هو المصدر الوحيد للواجبات والدرجات، وحذفت الشاشات المكررة التي أضيفت في البداية. بذلك لا توجد نسختان مستقلتان من تسليم الواجب أو تصحيح المعلم.

## 2. الحضور والغياب
الملف: mobile/src/features/modules/screens/attendance-screen.tsx

### ولي الأمر
- سجل حضور الأبناء عبر attendance/me/children/records/.
- درجات المواظبة عبر attendance/me/children/scores/.
- طلبات الأعذار عبر attendance/excuses/.
- يرسل طلب العذر باستخدام الطالب الذي أعاده app/my/children/ فقط؛ ولا يسمح بإدخال طالب عشوائي.
- تواريخ البداية والنهاية تتحقق من الصيغة والترتيب قبل الإرسال.
- الاعتماد أو الرفض يبقى إجراءً إدارياً على الخادم.

### المعلم
- يحمّل الإسنادات من app/teacher-assignments/.
- حالات الحضور من attendance/status-types/.
- طلاب الشعبة والسنة من students/?section=...&academic_year=....
- يقرأ السجل الحالي من attendance/registers/.
- يفتح السجل عبر attendance/registers/open/.
- يحفظ الرصد جماعياً عبر bulk-record ثم يرسل السجل عبر submit.
- حالات الطلاب الأولية تُقرأ من StudentAttendanceRecord الذي أنشأه الخادم، بما فيها الغياب بعذر معتمد؛ ولا يستبدل التطبيق القيم المبدئية بتخمين محلي.
- تستخدم كل حالات الحضور النشطة المعرفة في المدرسة، ولا تقتصر الواجهة على present/absent/late.

### الإدارة
- مساحة الإدارة تعرض سجلات الحضور بحالة submitted فقط، وتتيح اعتمادها عبر POST attendance/registers/{id}/approve/.
- تعرض طلبات الأعذار بحالة submitted فقط، وتتيح قبولها أو رفضها مع ملاحظات المراجع عبر POST attendance/excuses/{id}/review/.
- يطبق الخادم التحقق من ATTENDANCE_ADMIN_ROLES ويمنع اعتماد أي سجل لم يرسل للمراجعة أو مراجعة عذر تمت معالجته؛ التطبيق لا يغير الحالة محلياً.

### الحد المعروف
لا يوجد في عقد API الذي راجعناه مسار قراءة ذاتية لسجل الطالب؛ مسارات me/children مخصصة لولي الأمر المرتبط. لذلك لا تعرض الشاشة بيانات ولي أمر للطالب ولا تتجاوز حدود الصلاحيات.

## 3. الاختبارات الإلكترونية
الملف: mobile/src/features/modules/screens/exams-screen.tsx
- قائمة الاختبارات المنشورة من app/online-exams/.
- بدء/استكمال محاولة من /{exam_id}/start/.
- جلب ورقة الأسئلة من /{exam_id}/paper/؛ لا يعيد هذا المسار الإجابات الصحيحة.
- إرسال الإجابات ككائن question_id -> answer إلى /{exam_id}/submit/.
- يعتمد الخادم حساب الدرجة الموضوعية ووقت الانتهاء وحالة المحاولة.
- لا يحتسب الهاتف درجات ولا يقبل تسليم محاولة منتهية.
- الإجابات المكتوبة لا تحفظ على الخادم أثناء التحرير؛ تُرسل عند التسليم النهائي فقط. تعرض الشاشة تنبيهاً صريحاً بهذا القيد.

## 4. الملف المالي
الملف: mobile/src/features/modules/screens/fees-screen.tsx
- كشف حساب الطالب عبر fees/students/{student_id}/statement/.
- اختيار الابن لدى ولي الأمر من app/my/children/ أو الملف الدراسي للطالب من app/account/profiles/.
- يعرض إجمالي الفواتير والخصومات والمدفوع والمتبقي والرصيد الدائن ورصيد دفتر الأستاذ.
- يعرض أعمار المتأخرات، الفواتير، الأقساط، سندات القبض وحركات الرصيد الدائن، مع بيان السندات والحركات المعكوسة.
- يعرض تحذيراً إذا كان رصيد الطالب لا يطابق آخر رصيد في سجل الحركات.
- لا يحتوي على عمليات دفع أو إنشاء سند قبض أو إلغاء أو عكس؛ هذه إجراءات مالية محكومة بصلاحيات وخدمات الخادم.

## 5. الإشعارات
الملف: mobile/src/features/modules/screens/notifications-screen.tsx
- GET notifications/ لقائمة الإشعارات وعدد غير المقروء.
- POST notifications/{id}/read/ لتمييز إشعار واحد.
- POST notifications/ لتمييز الكل.
- app/notification-preferences/ لقراءة التفضيلات المسجلة، وPATCH لتغيير حالة تفضيل موجود.
- لا يخترع التطبيق تصنيفات أو قنوات جديدة؛ يعرض فقط ما يرجعه الخادم.
- تسجيل Push Device موجود في الخادم، لكن apps/notifications/services.py لا يحتوي حالياً خدمة إرسال Push؛ لم نعرض ذلك على أنه مكتمل.

## 6. المحادثات
الملف: mobile/src/features/modules/screens/messages-screen.tsx
- قائمة محادثات المستخدم كمشارك نشط عبر app/conversations/.
- قراءة الرسائل وإرسال النصوص وقراءة المحادثة وكتمها عبر المسارات الخاصة بالمحادثة.
- تحديث دوري للمحادثات والرسائل باستخدام REST؛ لا WebSocket مؤكد في عقد الخادم.
- لا يعرض التطبيق دليلاً عاماً للمستخدمين ولا يتيح محادثة مع طرف عشوائي.
- المرفقات لا تزال غير مربوطة في واجهة الهاتف، ومسار الخادم الحالي يعيد أول 100 رسالة فقط ولا يوفر واجهة تحميل دفعة الرسائل اللاحقة.

## 7. العزل والتخزين المؤقت
أضيف hook موحد useModuleQueryScope يضيف user ID وsession ID وschool ID إلى مفاتيح Query Cache في الشاشات التشغيلية، مع استمرار مسح الذاكرة عند تبديل المدرسة أو الدور أو تسجيل الخروج. القصد منع إعادة استخدام نتيجة وحدة من حساب أو مدرسة مختلفة.

## 8. مسارات التطبيق
- /academics: الواجبات والدرجات.
- /attendance: الحضور والغياب.
- /exams: الاختبارات الإلكترونية للطالب.
- /fees: الملف المالي للطالب وولي الأمر.
- /messages: المحادثات.
- /notifications: الإشعارات والتفضيلات.

تم ربط الاختصارات ذات الصلة في لوحة البداية بحسب الدور، ولم نعرض اختصار حضور ذاتي للطالب لغياب API مخصص. مساحة الإدارة في /attendance تتيح اعتماد سجلات الحضور المرسلة ومراجعة الأعذار المعلقة وفق صلاحيات الخادم.

## 9. ما لم يكتمل
- حضور الطالب الذاتي يحتاج مسار API مخصصاً.
- إجابات الاختبارات لا تحفظ مسودة على الخادم أثناء الكتابة؛ يتم حفظها عند الإرسال النهائي.
- واجهة المحادثات لا ترسل أو تنزل المرفقات، ولا تجلب دفعات إضافية من الرسائل.
- خدمة إرسال إشعارات Push الخلفية وإعدادات مزود Android/iOS لم تكتمل.
- لا توجد هنا بوابة دفع أو عمليات تحصيل مالية.
- لم يُبن APK ولم يتم اختبار الوحدات بحسابات حقيقية على هاتف مادي.
- يلزم التحقق من تشغيل Mobile CI على أحدث SHA بعد هذه التعديلات قبل اعتبار الدفعة مجتازة.
