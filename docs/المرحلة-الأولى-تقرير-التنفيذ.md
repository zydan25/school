# تقرير المرحلة الأولى — نواة منصة School
الإصدار: 0.1.0 — التاريخ: 30 أكتوبر 2026 — الحالة: تنفيذ تأسيسي أولي، وليس إصدار إنتاج.

## 1. الهدف
إرساء نواة موحدة للمنصة قبل وظائف الطلاب والمعلمين والجدول والمحاسبة المدرسية، مع فصل صلاحيات المنصة المركزية عن صلاحيات كل مدرسة.

## 2. التطبيقات الموجودة في حزمة المرحلة الأولى
| التطبيق | النطاق |
|---|---|
| core | نماذج UUID والتواريخ والأرشفة والملكية المدرسية، موقع الإدارة والقائمة ولوحة المؤشرات |
| accounts | مستخدم برقم الهاتف، صلاحيات مركزية، عضويات المدارس، الأدوار، الدعوات |
| tenants | المدارس والفروع والنطاقات والإعدادات وMiddleware وسياق المدرسة وخدمات التهيئة |
| academics | السنوات والفصول والمراحل والصفوف والقاعات والشعب والمواد والفترات وأيام العمل |
| platform | الميزات والباقات والاشتراكات وتجاوز الميزات وفواتير ومدفوعات اشتراك المنصة |
| notifications | القوالب والإشعارات والتفضيلات وOutbox |
| auditlog | أحداث التدقيق مع منع التعديل والحذف الاعتيادي |
| api | فحص الصحة والهوية والمدارس المتاحة وتبديل سياق المدرسة |

## 3. ملفات وبنية التشغيل
توجد إعدادات منفصلة للتطوير والاختبار وCI والإنتاج؛ PostgreSQL للإنتاج وSQLite للاختبارات؛ WSGI/ASGI وURLs للإدارة وAPI؛ Django REST Framework وDjango Unfold؛ قوالب وCSS/JS عربية RTL؛ Dockerfile وCompose وMakefile وGitHub Actions CI؛ وملف بيئة نموذجي دون أسرار حقيقية.

## 4. عزل المدارس
كل كيان تشغيلي مدرسي يحمل مرجع المدرسة، وتتحقق العضوية في سياق الطلب قبل السماح بالوصول. يمكن للمستخدم امتلاك عضويات في مدارس مختلفة مع اختيار سياق واحد للطلب. الأدوار المدرسية تتبع المدرسة التي أنشأتها، ولا يسمح بإسناد دور مدرسة إلى عضوية مدرسة أخرى.

## 5. الفصل المحاسبي
فواتير ومدفوعات تطبيق platform تخص اشتراك المدرسة في منصة School فقط. لا تمثل إيرادات المدرسة أو رسوم الطلاب أو دفتر الأستاذ المدرسي. المحاسبة المدرسية المستقلة تنفذ في تطبيق accounting منفصل؛ لكل مدرسة دليل حسابات وفترات وقيود وأرصدة تخصها. لا يوجد دفتر محاسبي مشترك بين المدارس.

## 6. لوحتا الإدارة
/admin/ لإدارة المنصة والمستخدمين والباقات والاشتراكات والتدقيق.
/school-admin/ لإدارة المدرسة المختارة فقط مع تصفية القوائم في QuerySets وإعادة التحقق من نطاق المدرسة في كل طلب.
تم تخصيص Unfold باتجاه RTL وألوان وهوية وتنقل ومؤشرات، لكن الواجهة التشغيلية الخارجية في React ليست جزءاً من هذه المرحلة.

## 7. API الأولي
GET /api/v1/health/ لفحص الخدمة.
GET /api/v1/me/ لهوية المستخدم وسياق المدرسة.
GET /api/v1/schools/ للمدارس المتاحة للمستخدم.
POST /api/v1/school-context/ لاختيار سياق مدرسة بعد التحقق.
JWT وتجربة Flutter لم تعتمدا بعد.

## 8. ما لم ينفذ بعد
ملفات الطلاب والقبول وأولياء الأمور؛ المعلمون والموظفون؛ الجدول الفعلي والحصص؛ الحضور؛ الدروس والواجبات؛ الاختبارات والدرجات؛ رسوم الطلاب؛ دفتر الأستاذ المدرسي؛ الرواتب والمشتريات والمخزون؛ المكتبة والنقل والعيادة؛ React وFlutter والإرسال الفعلي لقنوات الإشعار.

## 9. الفحوص والقيود الحالية
تم إجراء compileall لملفات Python. لم يتم تشغيل فحوص Django أو migrations أو pytest في بيئة تجهيز الملفات لعدم وجود Django واعتمادياته مثبتة وتعذر الاتصال بمدير الحزم. لم تولد migrations الأولية بعد، ويجب تثبيت الاعتماديات وتشغيل makemigrations ومراجعة الناتج قبل الاعتماد. يلزم PostgreSQL فعلي ومراجعة لوحتي الإدارة في متصفح. لا تستخدم بيانات حقيقية قبل نجاح اختبارات العزل والمراجعة الأمنية.

## 10. معيار إغلاق المرحلة
1. تثبيت الاعتماديات من requirements.
2. نجاح python manage.py check.
3. توليد migrations ومراجعتها وتطبيقها على PostgreSQL نظيف.
4. نجاح اختبارات العزل والأدوار والاشتراكات والتدقيق وAPI.
5. اختبار مستخدمين من مدرستين في لوحتي الإدارة.
6. اختبار ملفات RTL وCSS/JS بعد النشر.
7. تحديث التقرير برقم الالتزام ونتائج الاختبارات.
