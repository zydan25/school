# وحدات الهاتف المتصلة بالخادم

هذه الوحدة تجمع شاشات الخدمات المشتركة وواجهات API، ولا تحتوي على بيانات مدرسية افتراضية للتشغيل الحقيقي.

## الشاشات
- attendance: ولي الأمر يعرض سجلات الأبناء والمواظبة ويرسل طلب عذر؛ المعلم يرصد حضور الشعبة المسندة ويرسل السجل للمراجعة.
- exams: الطالب يبدأ اختباراً منشوراً، يجلب الورقة، ثم يرسل الإجابات النهائية.
- fees: الطالب وولي الأمر يقرآن كشف الحساب فقط.
- messages: قائمة المحادثات المصرح بها والرسائل النصية والقراءة والكتم.
- notifications: الإشعارات المسجلة وتفضيلات القنوات المعرفة مسبقاً.

## قواعد البيانات والاعتماد
- كل قراءات وكتابات تستخدم authenticatedRequest أو authenticatedListRequest.
- مفاتيح Query Cache تشمل الحساب ومعرف الجلسة والمدرسة النشطة.
- لا يعتمد التطبيق العذر، أو سجل الحضور، أو الاختبار، أو التصحيح، أو أي عملية مالية محلياً؛ الخادم يقرر النتيجة.
- لا تستخدم القائمة الكاملة للطلاب أو بيانات المدرسة العامة لتحديد صلاحيات مستخدم؛ الخادم يعيد النتائج المصرح بها فقط.
- صفحات الطلاب والشعب تستخدم آلية pagination المعتمدة وتتحقق من نطاق المضيف عند متابعة روابط الصفحات.
- عدم وجود API ذاتي لحضور الطالب لا يُعالج بتوسيع صلاحيات ولي الأمر؛ تعرض الشاشة حدود الخدمة الحالية.

## حدود لا يجب إخفاؤها
- الاختبار الإلكتروني يحفظ الإجابات عند التسليم النهائي؛ لا يوجد API مسجل لحفظ مسودة كل إجابة.
- المحادثات النصية متصلة، لكن إرسال المرفقات وتنزيلها لم يربطا بالهاتف بعد. الخادم يعيد حتى 100 رسالة في هذا المسار ولا يوفر واجهة تحميل الدفعة التالية.
- الإشعارات داخل التطبيق وتفضيلاتها متصلان؛ إرسال Push يحتاج استكمال خدمة الخلفية وإعدادات مزود المنصة.
- عمليات الرسوم هنا قراءة فقط؛ لا يوجد دفع أو إنشاء سند قبض أو إلغاء سند من واجهة الطالب/ولي الأمر.
